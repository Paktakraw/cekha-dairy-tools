# การทดสอบ

## เทสต์อัตโนมัติ

```bash
npm test
```

ใช้ตัวรันเทสต์ที่มากับ Node (`node:test`) จึงไม่ต้องติดตั้งไลบรารีเพิ่ม ไฟล์เทสต์อยู่ใน `tests/` และรันไฟล์ TypeScript ได้โดยตรง (ต้องใช้ Node 22.18 ขึ้นไป)

| ไฟล์ | ทดสอบอะไร |
|---|---|
| `tests/pool.test.ts` | ตรรกะการสุ่ม: รวม pool จากหลายกลุ่ม, แยก Current/Excluded, ข้ามรายการที่ถูกลบ, สุ่มจนหมดโดยไม่ซ้ำ, รายการชื่อซ้ำต่างกลุ่ม |
| `tests/summary.test.ts` | สรุปรายรับ-รายจ่าย: ผลรวม, ทศนิยมไม่คลาดเคลื่อน, สรุปตามหมวดหมู่, กรณีว่าง, หมวดหมู่ไม่พบ |
| `tests/format.test.ts` | รูปแบบเงิน (฿1,000.00) และวันที่ (ไม่เพี้ยนวันเพราะ timezone) |
| `tests/calorie.test.ts` | BMR (Mifflin-St Jeor) / TDEE, validation ช่วงค่า, แคลอรี่ต่อรายการ (ปัดครั้งเดียว), สรุปรายวัน/สัปดาห์/เดือน, ยูทิลิตี้วันที่ (สัปดาห์จันทร์–อาทิตย์) |
| `tests/unitPrice.test.ts` | เทียบราคาต่อหน่วย: validation ราคา/ปริมาณ/ชื่อ, แปลงหน่วย (มก./ก./กก., มล./ล., ชิ้น), หาตัวที่ถูกที่สุดและ % ที่แพงกว่า, ราคาเท่ากัน, หน่วยคนละกลุ่ม, รูปแบบตัวเลข |
| `tests/theme.test.ts` | `resolveTheme`: ค่าเริ่มต้นสว่าง, รับ light/dark, ค่าที่ไม่รู้จักถือเป็นสว่าง |

ขอบเขตของเทสต์อัตโนมัติคือ **pure functions เท่านั้น** (ไม่แตะ Supabase หรือ UI) ถ้าเพิ่ม logic ล้วน ๆ ใหม่ให้แยกไว้ใน `utils/` แล้วเพิ่มเทสต์ที่นี่

คำสั่งตรวจอื่นที่ควรรันก่อนส่งงานทุกครั้ง: `npm run lint` และ `npm run build`

## การตรวจ Database (RLS)

ตรวจแบบอ่านอย่างเดียวด้วยผู้ใช้ที่ไม่ได้ล็อกอิน (ใช้ publishable key อย่างเดียว) ผลที่ถูกต้องคือ **ได้ `[]` ไม่ใช่ข้อมูลจริง** แม้ในตารางจะมีข้อมูลอยู่:

```bash
curl "$VITE_SUPABASE_URL/rest/v1/tasks?select=id&limit=1" -H "apikey: $VITE_SUPABASE_PUBLISHABLE_KEY"
```

ตรวจซ้ำกับตาราง `random_groups`, `random_items`, `categories`, `transactions` ได้เช่นกัน และการเรียก `rpc/seed_default_categories` ด้วย key เดียวกันต้องได้ `permission denied`

การทดสอบว่าผู้ใช้สองคนแยกข้อมูลกันจริง ให้เปิดแอปจากสองเบราว์เซอร์ (หรือหน้าต่าง Incognito) แล้วเช็กว่าไม่เห็นข้อมูลของกันและกัน

## รายการตรวจด้วยมือ (CRUD และ Edge Cases)

ทดสอบในเบราว์เซอร์ทั้งหน้าจอคอม (กว้าง ≥ 1024px) และมือถือ

### รายการงาน (`/todo`)
- [ ] เพิ่มงานโดยเว้นชื่อว่าง → ขึ้นข้อความเตือน ไม่บันทึก
- [ ] เพิ่มงานชื่อซ้ำ (เช่น "งาน A" กับ "  งาน a ") → ถูกปฏิเสธ มีข้อความใต้ช่องชื่อ
- [ ] พิมพ์ชื่อเกิน 100 ตัวอักษร / รายละเอียดเกิน 1,000 → พิมพ์ต่อไม่ได้ ตัวนับแสดงถูก
- [ ] เปลี่ยนสถานะ รอดำเนินการ → กำลังทำ → เสร็จแล้ว: สีเปลี่ยน, เสร็จแล้วแสดง "เสร็จเมื่อ", เปลี่ยนกลับแล้วเวลาหาย
- [ ] เพิ่มงานเกิน 10 รายการ → มีแบ่งหน้า; ลบรายการสุดท้ายของหน้าสุดท้าย → ถอยกลับหน้าก่อนหน้า ไม่ว่าง
- [ ] Filter สถานะทีละค่าและหลายค่า → แบ่งหน้าเริ่มที่หน้า 1; ไม่มีงานตรงตัวกรอง → ขึ้น Empty State
- [ ] ลบงาน → มี Confirm; รีเฟรชหน้า ข้อมูลยังอยู่
- [ ] เลื่อนรายการยาว ๆ → Header (ชื่อหน้า + ปุ่มเพิ่มงาน) ติดอยู่กับที่

### สุ่มเลือก (`/randomizer`)
- [ ] สร้างกลุ่มชื่อซ้ำ → ถูกปฏิเสธ; ชื่อเกิน 50 ตัวอักษรพิมพ์ไม่ได้
- [ ] เพิ่ม แก้ไข ลบ รายการ และลบกลุ่ม (รายการในกลุ่มหายไปด้วย มี Confirm)
- [ ] ปุ่มลูกศรยุบ/ขยายกลุ่ม และ "ยุบทุกกลุ่ม" ทำงาน
- [ ] เลือกหลายกลุ่ม → สุ่มจนครบทุกรายการโดยไม่ซ้ำ → ขึ้นข้อความให้กด "เริ่มสุ่มใหม่"
- [ ] ระหว่างสุ่มมี animation ประมาณ 1 วินาที และปุ่ม/ตัวเลือกกลุ่มถูกปิดชั่วคราว
- [ ] เปลี่ยนกลุ่มที่เลือกกลางคัน → รายการที่สุ่มไปแล้วถูกล้าง
- [ ] ลบรายการที่สุ่มไปแล้ว → หายจากรายการ "สุ่มไปแล้ว"; รีเฟรชหน้า → ผลการสุ่มหาย แต่กลุ่ม/รายการยังอยู่
- [ ] เลือกกลุ่มที่ไม่มีรายการ → ขึ้นข้อความแนะนำ ปุ่มสุ่มถูกปิด

### รายรับ-รายจ่าย (`/finance`)
- [ ] เปิดครั้งแรกมีหมวดหมู่เริ่มต้นภาษาไทยครบ (รายรับ 4, รายจ่าย 7) และรีเฟรชแล้วไม่ซ้ำ
- [ ] เพิ่มหมวดหมู่ชื่อซ้ำในประเภทเดียวกัน → ถูกปฏิเสธ; ชื่อซ้ำกันแต่คนละประเภท → ทำได้
- [ ] แก้ชื่อหมวดหมู่ → รายการเดิมยังอยู่และแสดงชื่อใหม่; ประเภทเปลี่ยนไม่ได้ตอนแก้ไข
- [ ] ลบหมวดหมู่ที่มีรายการใช้อยู่ → ลบไม่ได้ พร้อมข้อความอธิบาย; หมวดที่ไม่มีรายการ → ลบได้
- [ ] บันทึกรายการ: จำนวนเงิน 0, -5, `abc`, `1.234` → ถูกปฏิเสธ; `1500`, `99.5` → บันทึกได้
- [ ] เลือกวันที่ในอนาคต → ถูกปฏิเสธ; เปลี่ยนประเภทแล้วรายการหมวดหมู่เปลี่ยนตาม
- [ ] บันทึกสำเร็จ → ฟอร์มรีเซ็ต และรายการล่าสุดแสดงรายการใหม่; Toggle ประเภทกรองรายการล่าสุดได้
- [ ] หน้าสรุป: การ์ดและแถบสัดส่วนเปลี่ยนตามตัวกรอง (เดือน/ปี, ช่วงวันที่, ประเภท, หมวดหมู่, ค้นหา)
- [ ] ช่วงวันที่ที่วันเริ่ม > วันสิ้นสุด → ขึ้นข้อความเตือน
- [ ] ปุ่ม "ล้างตัวกรอง" คืนค่าทั้งหมด; ไม่มีรายการตรงตัวกรอง → ขึ้น Empty State
- [ ] ตารางประวัติแก้ไขและลบได้ และแบ่งหน้า 10 รายการ
- [ ] section "เพิ่มรายการ" และ "ตัวกรอง" เปิดมาแบบย่อไว้ กดลูกศรมุมขวาแล้วขยายได้

### แคลอรี่ (`/calorie`)
ต้องรัน `20261110000200_calorie.sql` ก่อน
- [ ] เปิด `/calorie` → ไปหน้า "บันทึกอาหาร"; เปิดครั้งแรกมีรายการอาหารตั้งต้น 102 เมนู (หน้า "รายการอาหาร") และรีเฟรชแล้วไม่ซ้ำ
- [ ] หน้า BMR: อายุ 9/101, น้ำหนัก 19/301, ส่วนสูง 99/251, ค่าว่าง, `abc` → ถูกปฏิเสธ; ชาย 30 ปี 70 กก. 175 ซม. → BMR 1,649 kcal; เลือกระดับกิจกรรมแล้ว TDEE = BMR × ตัวคูณ
- [ ] กด "คำนวณและบันทึก" แล้วรีเฟรชหน้า → ฟอร์มและผลลัพธ์ยังอยู่ (บันทึกที่ Supabase); คำนวณซ้ำ → อัปเดตทับ ไม่เกิดแถวใหม่
- [ ] เพิ่มอาหาร: ค้นหาชื่อ → เลือก → เห็นแคลอรี่ต่อหน่วยและแคลอรี่ที่ได้ตามจำนวนหน่วย; ไม่เลือกอาหาร/จำนวน 0, -1, `abc`, 101 → ถูกปฏิเสธ; วันที่อนาคต → ถูกปฏิเสธ
- [ ] รายการจัดกลุ่มตามมื้อ แสดงยอดรวมรายมื้อและรวมทั้งวัน; แถบเทียบ TDEE เปลี่ยนเป็นสีแดงเมื่อเกินเป้าหมาย; ถ้ายังไม่คำนวณ BMR ขึ้นลิงก์ไปคำนวณ
- [ ] เลื่อนวันก่อนหน้า/ถัดไป/เลือกวัน/ปุ่ม "วันนี้" ได้ ย้อนหลังได้ทุกวัน เดินหน้าเกินวันนี้ไม่ได้
- [ ] แก้ไขรายการ (วันที่/มื้อ/จำนวน) และลบ (มี Confirm) ได้; แก้แคลอรี่ของอาหารในหน้า "รายการอาหาร" แล้วรายการที่บันทึกไว้ก่อนหน้า **ไม่เปลี่ยน**
- [ ] หน้า "รายการอาหาร": เพิ่มชื่อซ้ำ (ต่างตัวพิมพ์/มีช่องว่างหัวท้าย) → ถูกปฏิเสธ; แก้ไข/ลบอาหารตั้งต้นได้; ลบอาหารที่เคยบันทึกกินแล้ว → ประวัติยังอยู่; ค้นหาและแบ่งหน้า 10 รายการ
- [ ] หน้า "สรุป": สลับรายสัปดาห์/รายเดือน, เลื่อนช่วงย้อนหลังได้ เดินหน้าเกินช่วงปัจจุบันไม่ได้; รวม/เฉลี่ยต่อวัน (เฉพาะวันที่มีบันทึก)/จำนวนวันที่บันทึก/เทียบ TDEE ถูกต้อง; ช่วงที่ไม่มีบันทึก → Empty State
- [ ] ปิดเน็ต/เปลี่ยนวัน → ขึ้น Error พร้อมปุ่ม "ลองใหม่"

### เทียบราคาต่อหน่วย (`/unit-price`)
ไม่ใช้ฐานข้อมูล ไม่ต้องรัน migration
- [ ] เปิด `/unit-price` → มี 2 ตัวเลือกวางเป็น 2 คอลัมน์เคียงกัน (ทั้งคอมและมือถือ), ปุ่ม "เปรียบเทียบ" และข้อความ "กรอกข้อมูลแล้วกด “เปรียบเทียบ”" (ยังไม่แสดงผล)
- [ ] A: 100 บาท 500 ก. / B: 150 บาท 1 กก. → กด "เปรียบเทียบ" แล้ว B มีป้ายสีเขียว "คุ้มที่สุด" (0.15 บาท/ก.) A แสดง "แพงกว่า 33.3%"; แก้ตัวเลขใดก็ตามแล้วผลหายไป ต้องกดใหม่
- [ ] เปลี่ยน "แสดงราคาต่อ" เป็น 1 ก. / 100 ก. / 1 กก. → ตัวเลขเปลี่ยน (B = ฿0.1500 / ฿15.00 / ฿150.00) แต่ตัวที่คุ้มที่สุดและ % ไม่เปลี่ยน
- [ ] ราคาเท่ากัน (100 บาท 500 ก. กับ 200 บาท 1 กก.) → ขึ้น "ราคาเท่ากัน" ไม่มีป้าย "คุ้มที่สุด"
- [ ] เลือกหน่วยคนละกลุ่ม (กรัมกับมิลลิลิตร) → ขึ้นข้อความว่าเทียบกันไม่ได้
- [ ] ราคา/ปริมาณเป็น 0, -1, `abc`, 10.123 (ราคา), เกิน 1,000,000, กรอกแค่ช่องเดียว → ขึ้นข้อความที่ช่องนั้นและตัวเลือกนั้นไม่ถูกนำไปเทียบ
- [ ] กดเปรียบเทียบเมื่อกรอกไม่ครบ 2 ตัวเลือก → ขึ้น "กรอกราคาและปริมาณอย่างน้อย 2 ตัวเลือก"
- [ ] ปุ่ม "เพิ่มตัวเลือก" เพิ่มได้ถึง 3 (กลายเป็น 3 คอลัมน์) แล้วปุ่มถูกปิด; ลบได้จนเหลือ 2 (ไม่มีปุ่มลบเมื่อเหลือ 2)
- [ ] ชื่อพิมพ์ได้ไม่เกิน 50 ตัวอักษร; ตัวเลือกไม่มีชื่อแสดงเป็น "ตัวเลือกที่ N"
- [ ] มือถือ (3 คอลัมน์): ช่องกรอก/ข้อความ error/dropdown หน่วยไม่ล้นหรือซ้อนกัน ไม่ต้องเลื่อนซ้ายขวา

ต้องรัน `20261113000100_user_preferences.sql` ก่อน
- [ ] เปิดแอปครั้งแรก (หรือบัญชีใหม่) → โหมดสว่าง ไม่ว่าเครื่องตั้งโหมดมืดไว้หรือไม่

- [ ] กดพระจันทร์ → ทั้งแอปเปลี่ยนเป็นมืดทันที ไม่ reload; กดพระอาทิตย์ → กลับสว่าง
- [ ] Sidebar ย่อ: ปุ่มเรียงแนวตั้งและไม่ล้นแถบ; ขยาย: เรียงแนวนอน
- [ ] รีเฟรชหน้า → ยังเป็นโหมดที่เลือกไว้ และ **ไม่วาบขาว** ตอนเปิดในโหมดมืด
- [ ] ตรวจใน Supabase (Table Editor → `user_preferences`) มี 1 แถวของผู้ใช้ และ `theme` ตรงกับที่เลือก; สลับซ้ำ → แถวเดิมอัปเดต ไม่เกิดแถวใหม่
- [ ] ล้างแคช localStorage ของเบราว์เซอร์ (แต่คง session) แล้วรีเฟรช → โหลดโหมดมืดจาก Supabase ได้ (อาจวาบขาวครั้งเดียวและกลับมาเป็นมืด)

- [ ] ตรวจสายตาโหมดมืดทุกหน้า: หน้าหลัก, To-do, สุ่มเลือก, รายรับ-รายจ่าย (ตัวเลขเขียว/แดง, ป้ายหมวดหมู่), แคลอรี่ (แถบเกินเป้าหมาย), เทียบราคาต่อหน่วย (ป้ายเขียว "คุ้มที่สุด"), Modal/Dialog/Toast, Dropdown และช่องกรอก — ตัวอักษรอ่านออก ไม่มีพื้นขาวหลงเหลือ ไม่มีตัวอักษรกลืนพื้น
- [ ] ปุ่มหลัก (พื้นเข้มตัวอักษรขาวในโหมดสว่าง) ในโหมดมืดเป็นพื้นสว่างตัวอักษรมืด อ่านออกและเห็นสถานะที่เลือกชัด (แท็บ, ตัวกรอง, Sidebar ที่เลือกอยู่)
