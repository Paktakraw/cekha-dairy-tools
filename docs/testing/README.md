# เอกสารการทดสอบ

โฟลเดอร์นี้เก็บ **ข้อมูล test case** และ **ผลการทดสอบ** ของทั้งแอป

| ไฟล์ | เนื้อหา |
|---|---|
| [test-cases.md](test-cases.md) | แคตตาล็อกเคสทดสอบทั้งหมด พร้อมรหัสเคส: เทสต์อัตโนมัติ (143), เคสทำด้วยมือ (111), เคสฐานข้อมูล (13) |
| [test-results.md](test-results.md) | ผลการรันล่าสุด: lint/build/เทสต์อัตโนมัติ, ผลฐานข้อมูล, สถานะการทดสอบด้วยมือ, ผลตรวจโค้ด, ปัญหาที่ยังเปิด และแบบฟอร์มบันทึกผลรอบถัดไป |

เอกสารเดิมที่ยังใช้งานอยู่: [docs/testing.md](../testing.md) — วิธีรันเทสต์ เช็กลิสต์ติ๊กตรวจด้วยมือ และขั้นตอนรีวิวโค้ดก่อน commit (แหล่งต้นทางของเคสทำด้วยมือใน test-cases.md)

## วิธีรัน
```bash
npm run lint     # ตรวจโค้ดด้วย oxlint
npm run build    # ตรวจ TypeScript แล้ว build
npm test         # เทสต์อัตโนมัติ (node:test) ต้องใช้ Node 22.18 ขึ้นไป
```

## ขอบเขตของการทดสอบ
| ระดับ | ทำอย่างไร | ครอบคลุม |
|---|---|---|
| Unit | `npm test` | pure function ใน `utils/` ของทุกฟีเจอร์ (ยกเว้น To-do ที่ logic อยู่ที่ DB/หน้าจอ) |
| ฐานข้อมูล | ทดสอบบน PostgreSQL ชั่วคราวด้วย psql + ตรวจ Supabase จริงแบบอ่านอย่างเดียว | migration, CHECK/UNIQUE/FK, RLS, RPC |
| ทำงานจริง | เช็กลิสต์ด้วยมือใน `docs/testing.md` | CRUD, edge case, responsive, โหมดมืด |
| ไม่มี | UI/E2E, เทสต์ service/hook | ต้องเพิ่มไลบรารี รอผู้ใช้ยืนยัน |

## กฎ
- ก่อนเปิด Pull Request ต้องอัปเดต `test-cases.md` (ถ้าเพิ่ม/แก้เทสต์หรือเช็กลิสต์) และ `test-results.md` (ผลรอบล่าสุด) ให้ตรงกับโค้ด ดู [CLAUDE.md](../../CLAUDE.md) ข้อ 10.11
- ห้ามเขียนผลว่า "ผ่าน" ในเคสที่ไม่ได้รันจริง ถ้ายังไม่ได้ทดสอบให้เขียนว่า "ยังไม่ได้ทดสอบ"
- เอกสารภาพรวมของระบบและ requirement: [docs/spec/](../spec/)
