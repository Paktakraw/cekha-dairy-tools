# Feature: Calorie (คำนวณแคลอรี่)

- **ID:** `calorie`
- **Route:** `/calorie/*`
- **Folder:** `src/features/calorie/`
- **Status:** In scope (Phase 8) — spec ผู้ใช้ยืนยันแล้ว (2026-11-10), โค้ดเสร็จ รอผู้ใช้รัน migration และทดสอบ

## Overview
โมดูลแคลอรี่ มี 2 ฟังก์ชันหลัก:
1. **คำนวณ BMR / TDEE** — พลังงานที่ร่างกายใช้ขณะพัก และรวมกิจกรรมประจำวัน
2. **คำนวณแคลอรี่จากอาหารที่กิน** — เลือกอาหารจากรายการ (มีข้อมูลตั้งต้นให้) ระบบแสดงแคลอรี่ให้ทันที ผู้ใช้ไม่ต้องกรอกเอง แล้วรวมเป็นรายมื้อ/รายวัน เทียบกับเป้าหมาย

## Requirements

### 1) คำนวณ BMR / TDEE (หน้า `/calorie/bmr`)
- กรอก: เพศ (ชาย/หญิง), อายุ (ปี), น้ำหนัก (กก.), ส่วนสูง (ซม.), **ระดับกิจกรรมประจำวัน (dropdown)**
- สูตร BMR **Mifflin-St Jeor**:
  - ชาย: `10×น้ำหนัก + 6.25×ส่วนสูง − 5×อายุ + 5`
  - หญิง: `10×น้ำหนัก + 6.25×ส่วนสูง − 5×อายุ − 161`
- **TDEE = BMR (ที่ปัดเป็นจำนวนเต็มแล้ว) × ตัวคูณกิจกรรม** ปัดเป็นจำนวนเต็ม (ผู้ใช้ตรวจสอบเองได้จากตัวเลขที่เห็น) ตัวคูณมาตรฐาน 5 ระดับ (1.2 / 1.375 / 1.55 / 1.725 / 1.9) — ผู้ใช้ยืนยันให้ใช้ค่านี้ (ยังไม่ได้เทียบกับบทความ Petcharavej เพราะเปิดหน้าไม่ได้)
- แสดง BMR และ TDEE เป็น kcal/วัน (ปัดเป็นจำนวนเต็ม) พร้อมข้อความว่าเป็นค่าประมาณ ไม่ใช่คำแนะนำทางการแพทย์
- Validation: อายุ 10–100 (จำนวนเต็ม), น้ำหนัก 20–300 กก., ส่วนสูง 100–250 ซม. (error ใต้ช่องที่ผิด ไม่คำนวณ)
- ผลคำนวณล่าสุดบันทึกเป็นโปรไฟล์ (1 แถวต่อผู้ใช้) เพื่อใช้เทียบในหน้าบันทึกอาหาร

### 2) บันทึกอาหารที่กิน (หน้า `/calorie/food`)
- **เลือกอาหารจากรายการ** (ช่องค้นหา/กรองตามชื่อในรายการที่โหลดมา ไม่เรียก API ภายนอก) → แสดง "X kcal ต่อ 1 หน่วย" ทันที
- กรอก: วันที่ (ค่าเริ่มต้น = วันนี้), มื้อ (เช้า/กลางวัน/เย็น/ของว่าง), จำนวนหน่วย (ค่าเริ่มต้น 1, ทศนิยมได้ เช่น 0.5)
- แคลอรี่ของรายการ = แคลอรี่ต่อหน่วย × จำนวนหน่วย (pure function) แสดงสดในฟอร์มก่อนบันทึก
- รายการที่บันทึก **เก็บสำเนา** ชื่อ/หน่วย/แคลอรี่ ณ ตอนที่กิน (แก้หรือลบอาหารในรายการภายหลังไม่ทำให้ประวัติเปลี่ยน)
- ดูรายการตามวัน (เลื่อนวันก่อน/ถัดไป หรือเลือกวัน) จัดกลุ่มตามมื้อ แสดงรวมรายมื้อและรวมทั้งวัน
- แก้ไข (จำนวน/มื้อ/วันที่) และลบรายการ (ลบมี Confirmation Dialog)
- เทียบแคลอรี่รวมของวันกับ TDEE ที่บันทึกไว้ (โปรไฟล์มี TDEE เสมอเพราะบังคับเลือกระดับกิจกรรม; ถ้ายังไม่มีโปรไฟล์ แสดงลิงก์ไปคำนวณ)
- อาหารที่เป็นข้อมูลตั้งต้นแสดงป้าย **"ค่าโดยประมาณ"**

### 3) สรุปรายสัปดาห์/รายเดือน (หน้า `/calorie/summary`) — ผู้ใช้ขอเพิ่ม
- สลับ **รายสัปดาห์** (จันทร์–อาทิตย์) / **รายเดือน**; เลื่อนช่วงก่อนหน้าได้ไม่จำกัด ไปข้างหน้าได้ถึงช่วงปัจจุบัน
- แสดง: แคลอรี่รวม, **ค่าเฉลี่ยต่อวัน (เฉพาะวันที่มีบันทึก** เพื่อไม่ให้วันที่ลืมบันทึกดึงค่าเฉลี่ยลง), จำนวนวันที่บันทึก, เป้าหมาย TDEE พร้อมส่วนต่างของค่าเฉลี่ย
- รายวัน (เฉพาะวันที่ไม่เกินวันนี้) แต่ละวันมีแถบเทียบ TDEE; แยกตามมื้อพร้อมสัดส่วน %
- คำนวณฝั่ง client จากรายการที่ดึงตามช่วงวันที่ (pure function `summarizeRange`)

### 4) จัดการรายการอาหาร (หน้า `/calorie/foods`)
- ดู ค้นหา เพิ่ม แก้ไข ลบ อาหารของตัวเอง: ชื่อ, หน่วย (เช่น จาน/ถ้วย/ชิ้น), แคลอรี่ต่อ 1 หน่วย
- ข้อมูลตั้งต้นแก้ไขและลบได้เหมือนรายการที่ผู้ใช้เพิ่มเอง (ถ้าลบจนไม่เหลือเลย ระบบจะ seed ข้อมูลตั้งต้นกลับมาให้ตอนเปิดหน้าครั้งถัดไป — พฤติกรรมเดียวกับหมวดหมู่ใน Finance)
- ค้นหาตามชื่อ แบ่งหน้า 10 รายการ
- ชื่อห้ามซ้ำ (ไม่สนช่องว่างหัวท้าย/ตัวพิมพ์เล็กใหญ่) แสดงข้อความชัดเจนเมื่อซ้ำ
- ลบมี Confirmation Dialog

### ทั่วไป
- Validation (บังคับทั้ง DB และ Form): ชื่ออาหาร ไม่ว่าง ≤ 100, หน่วย ไม่ว่าง ≤ 20, แคลอรี่ต่อหน่วย 0–10,000, จำนวนหน่วย > 0 และ ≤ 100
- มี Loading, Error, Empty State และ Toast ตามกฎกลาง ปุ่มมีไอคอน + tooltip + aria-label

### Technical Notes
- pure function ใน `utils/`: `calculateBmr`, `calculateTdee`, `validateBmrInput`, `entryCalories`, `summarizeDay` มีเทสต์ใน `tests/calorie.test.ts`
- รวมแคลอรี่เป็นจำนวนเต็ม kcal ของรายการ (ปัดครั้งเดียวต่อรายการ) แล้วรวม
- **ข้อมูลตั้งต้น:** 102 เมนู จากไฟล์ที่ผู้ใช้ให้มา ผ่านการแก้คำสะกด ("ก้วยเตี๋ยว" → "ก๋วยเตี๋ยว" 5 แถว, "กระเพรา" → "กะเพรา" 1 แถว) และตัดแถวซ้ำ ("ตำไทย" ซ้ำกับ "ส้มตำไทย") อยู่ที่ [`docs/features/calorie-foods-seed.csv`](calorie-foods-seed.csv) (คอลัมน์ name, serving_unit, kcal_per_unit)
- **ตัวเลขเป็นค่าประมาณ ยังไม่ได้ตรวจกับแหล่งทางการ** ที่มาของไฟล์ไม่ระบุ; แอปต้องแสดงว่าเป็นค่าโดยประมาณ ผู้ใช้ตรวจสุ่มกับ ThaiFCD ได้
- **ห้าม scrape/คัดลอกข้อมูลจากเว็บอื่น** (HDmall, ThaiFCD) ลงฐานข้อมูลโดยไม่ได้รับอนุญาต; ถ้าได้ไฟล์จาก INMU/HDmall ภายหลัง ให้นำเข้าผ่าน migration ใหม่ (คอลัมน์ `source` แยกที่มาได้)
- วิธีใส่ข้อมูลตั้งต้นให้ผู้ใช้: RPC `seed_default_foods()` (idempotent, security invoker, ทำงานเมื่อผู้ใช้ยังไม่มีอาหารเลย) แบบเดียวกับ `seed_default_categories()` ของ Finance เพื่อคง RLS `auth.uid() = user_id` โดยไม่ต้องมีตารางกลางที่ใครก็อ่านได้

## Database
ตาราง `calorie_profiles` (+ คอลัมน์มาตรฐานตาม CLAUDE.md ข้อ 6) — 1 แถวต่อผู้ใช้

| Field | Type | Rule |
|---|---|---|
| sex | text | NOT NULL, CHECK in ('male','female') |
| age | int | NOT NULL, CHECK 10–100 |
| weight_kg | numeric(5,1) | NOT NULL, CHECK 20–300 |
| height_cm | numeric(4,1) | NOT NULL, CHECK 100–250 |
| activity_level | text | NOT NULL, CHECK in 5 ระดับ (เช่น 'sedentary','light','moderate','active','very_active') |
| bmr | int | NOT NULL, CHECK > 0 |
| tdee | int | NOT NULL, CHECK > 0 |
| (user_id) | | UNIQUE (1 โปรไฟล์ต่อผู้ใช้), upsert |

ตาราง `foods` (+ คอลัมน์มาตรฐาน)

| Field | Type | Rule |
|---|---|---|
| name | text | NOT NULL, ไม่ว่าง, ≤ 100, UNIQUE (user_id, lower(btrim(name))) |
| serving_unit | text | NOT NULL, ไม่ว่าง, ≤ 20 |
| kcal_per_unit | numeric(7,1) | NOT NULL, CHECK 0–10000 |
| source | text | NOT NULL, CHECK in ('seed','user'), DEFAULT 'user' |

ตาราง `food_entries` (+ คอลัมน์มาตรฐาน)

| Field | Type | Rule |
|---|---|---|
| eaten_on | date | NOT NULL, DEFAULT current_date |
| meal | text | NOT NULL, CHECK in ('breakfast','lunch','dinner','snack') |
| food_id | uuid | NULL, FK → foods(id) ON DELETE SET NULL |
| food_name | text | NOT NULL, ไม่ว่าง, ≤ 100 (สำเนา ณ ตอนบันทึก) |
| serving_unit | text | NOT NULL, ≤ 20 (สำเนา) |
| kcal_per_unit | numeric(7,1) | NOT NULL, CHECK 0–10000 (สำเนา) |
| quantity | numeric(6,2) | NOT NULL, CHECK > 0 AND ≤ 100 |

Index: `user_id` ทุกตาราง, `food_entries(user_id, eaten_on)`, `foods(user_id, name)`
RLS: `auth.uid() = user_id` ทั้ง 4 คำสั่งทุกตาราง; migration แยกไฟล์ `<timestamp>_calorie.sql` (รวม RPC seed)

## Decisions (2026-11-10)
1. เลือกอาหารจากรายการแล้วระบบแสดงแคลอรี่ให้ (ผู้ใช้ไม่ต้องกรอกเอง) — ไม่ใช้ API ภายนอก เพราะไม่มี API อาหารไทยที่ฟรี ครอบคลุม และมีใบอนุญาตชัดเจน (Open Food Facts เน้นสินค้าบรรจุหีบห่อและจำกัด 10 ครั้ง/นาที, ThaiFCD ไม่มี API และสงวนลิขสิทธิ์, USDA เป็นอาหารอเมริกัน)
2. ข้อมูลตั้งต้นจากไฟล์ของผู้ใช้ (102 เมนู ต่อ 1 หน่วย) + ผู้ใช้เพิ่มเองได้ภายหลัง
3. มี dropdown ระดับกิจกรรมและแสดง TDEE ตามที่ผู้ใช้ขอ
4. รายการที่กินเก็บสำเนาข้อมูลอาหาร ณ ตอนบันทึก

5. ผู้ใช้ตอบ Open Questions (2026-11-10): บันทึกโปรไฟล์ลง Supabase; ใช้ตัวคูณมาตรฐานตามที่ใส่ไว้; สูตร Mifflin-St Jeor อย่างเดียว; ดูย้อนหลังได้ทุกวัน + สรุปเทียบรายสัปดาห์/รายเดือน; ชื่อเมนู "แคลอรี่"

## Out of Scope
- API อาหารภายนอก (Open Food Facts / USDA), สแกนบาร์โค้ด/รูปภาพ, macro (โปรตีน/คาร์บ/ไขมัน), BMI, กราฟเส้นย้อนหลัง (มีสรุปรายสัปดาห์/เดือนเป็นตัวเลขและแถบ), ติดตามน้ำหนักรายวัน, หน่วย lb/ft, หน่วยกรัมต่อ 100 กรัม (เวอร์ชันนี้ใช้ต่อหน่วยเท่านั้น), อาหารที่ใช้ร่วมกันระหว่างผู้ใช้
