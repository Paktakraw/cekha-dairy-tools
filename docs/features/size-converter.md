# Feature: Global Size Converter (ไซส์ไหนคือฉัน)

- **ID:** `size-converter`
- **Route:** `/size-converter`
- **Folder:** `src/features/size-converter/`
- **Status:** In scope (Phase 12) — **ร่าง spec รอผู้ใช้ตอบ Open Questions และยืนยัน**

## Overview
ช่วยคนสั่งเสื้อผ้า/รองเท้าจากต่างประเทศให้เลือกไซส์ถูก ผู้ใช้บันทึกสัดส่วนจริง (cm หรือ นิ้ว) ของตัวเองและคนรอบตัวไว้ครั้งเดียว
ระบบแปลงเป็นไซส์ของแต่ละมาตรฐาน (US / UK / EU / JP / KR / CN) ให้ทันที พร้อมคำแนะนำการเผื่อไซส์ และจดไซส์ที่เคยใส่ได้จริงของแต่ละแบรนด์
แนวคิดหลักคือ **Body-First**: ยึดสัดส่วนร่างกายเป็นตัวตั้ง ไม่ใช่แปลงตัวเลขไปมา

## Requirements

### ก. โปรไฟล์สัดส่วน (Size Profiles)
- สร้างได้หลายโปรไฟล์ (ตัวเอง แฟน ลูก พ่อแม่ ฯลฯ) สลับดูได้ในคลิกเดียว (ตัวเลือกโปรไฟล์อยู่บนสุดของหน้า) โปรไฟล์แรกตั้งเป็นของ "ฉัน"
- โปรไฟล์เก็บ: ชื่อ, กลุ่ม (ผู้ชาย / ผู้หญิง / เด็ก), และสัดส่วนทุกช่อง **ไม่บังคับ** (กรอกเท่าที่รู้):
  ความสูง, ความยาวเท้า, ความกว้างหน้าเท้า, รอบอก, รอบเอว, รอบสะโพก, รอบศีรษะ, รอบนิ้ว (สำหรับแหวน)
- สลับหน่วย cm / นิ้ว ได้ ข้อมูลเก็บใน DB เป็น **cm เสมอ** (รอบนิ้วเป็น mm ตามวงการแหวน) แปลงตอนแสดง/กรอก ค่าที่แปลงกลับต้องไม่เพี้ยนจากการปัดเศษซ้ำ (เก็บค่าที่ผู้ใช้กรอกแล้วแปลงครั้งเดียว)
- แก้ไข / ลบโปรไฟล์ได้ ลบต้องมี Confirmation Dialog และลบบันทึกไซส์ที่ผูกกับโปรไฟล์นั้นตาม (ถ้ามี)

### ข. ตัวแปลงไซส์ (Conversion Engine)
หมวด: รองเท้า, เสื้อ, กางเกง/กระโปรง (รวมกางเกงยีนส์), แหวน, หมวก
- เลือกโปรไฟล์ + หมวด → ระบบดึงสัดส่วนที่เกี่ยวข้องมาคำนวณ แสดงตารางเทียบทุกมาตรฐานพร้อมกัน
- ถ้าโปรไฟล์ยังไม่มีค่าที่หมวดนั้นต้องใช้ ให้แสดงข้อความบอกว่าขาดช่องไหน พร้อมปุ่มไปกรอก (ไม่เดาค่า)
- ผู้ใช้กรอกค่าชั่วคราวในหน้าตัวแปลงโดยไม่ต้องบันทึกโปรไฟล์ได้ (เช่น ลองวัดของเพื่อน)
- ผลลัพธ์ทุกค่าแสดงเป็น **ค่าประมาณ** พร้อมป้ายบอก และแสดงช่วงที่ใกล้เคียง (เช่น "EU 41.5–42") เมื่อค่าตกกลางระหว่างสองไซส์

#### สูตรรองเท้า (ผู้ใหญ่) — ฐาน: ความยาวเท้า (cm)
กำหนด **ส่วนเผื่อหัวรองเท้า = 1.7 cm (2 barleycorn)** ค่าเดียวใช้ทุกมาตรฐาน (ตรวจสูตรแล้วว่า EU ที่ใช้ 1.5 กับ UK ที่ใช้ 1.7 ทำให้ผลคลาดกันได้ ~0.3 ไซส์)

| มาตรฐาน | สูตร | ปัดเศษ |
|---|---|---|
| JP (cm) | = ความยาวเท้า (cm) | ปัดเป็น 0.5 cm |
| CN (mm, Mondopoint) / KR (mm) | = ความยาวเท้า (mm) | KR ปัดเป็น 5 mm, CN ปัดเป็น 5 mm |
| EU | = (เท้า cm + 1.7) × 1.5 (Paris point = ⅔ cm) | ปัดขึ้นเป็นครึ่งไซส์ |
| UK | = (เท้านิ้ว × 3) − 23 | ใกล้สุดครึ่งไซส์ |
| US ชาย | = UK + 1 | ใกล้สุดครึ่งไซส์ |
| US หญิง | = US ชาย + 1.5 (= UK + 2.5) | ใกล้สุดครึ่งไซส์ |

- ตรวจแล้ว: สูตร UK = 3L − 25 (L = ความยาวทำเท้า) เมื่อ L = เท้า + ⅔ นิ้ว จะได้ 3×เท้า − 23; US หญิงตามตารางส่วนใหญ่ห่างจาก US ชาย 1.5 ไซส์ (สูตรเดิม UK + 2 ห่างแค่ 1 ไซส์)
- **เด็ก:** ไม่ใช้สูตรผู้ใหญ่ (UK เด็กเริ่มนับต่างกัน ส่วนเผื่อมากกว่า) ใช้ตาราง lookup — ดู Open Questions ข้อ 3
- ค่าที่ได้เป็นไซส์ **มาตรฐานกลาง** ส่วนแบรนด์จริงอาจต่างไป ±0.5 ไซส์ (ดู Open Questions ข้อ 1)

#### สูตรแหวน — ฐาน: เส้นรอบนิ้ว (mm) หรือเส้นผ่านศูนย์กลางด้านใน (mm)
- เส้นรอบวง (mm) = เส้นผ่านศูนย์กลาง × π (กรอกอย่างใดอย่างหนึ่งได้)
- **ISO 8653 / JP** = เส้นรอบวง − 40 (52 mm → เบอร์ 12; JP 4 ≈ 44 mm) ปัดเป็นเลขจำนวนเต็ม
- **EU (เส้นรอบวงตรง ๆ)** = เส้นรอบวง (mm) เพราะร้านยุโรปจำนวนมากใช้แบบนี้ (52 mm = เบอร์ 52) → แสดง **ทั้งสองแบบพร้อมป้ายกำกับ** กันสับสน
- **US** = (เส้นผ่านศูนย์กลาง mm − 11.63) ÷ 0.8128 ปัดเป็น 0.25 (ตรวจแล้ว: 16.51 mm = US 6.0)
- **ไทย:** ไม่มีมาตรฐานเบอร์ที่ยืนยันได้ ไม่แสดงเป็นมาตรฐานแยกในเวอร์ชันนี้ (ร้านไทยส่วนใหญ่ใช้เบอร์ US หรือของร้านเอง)

#### สูตรหมวก — ฐาน: เส้นรอบศีรษะเหนือคิ้วราว 1 นิ้ว (cm)
- EU / เอเชีย = เส้นรอบศีรษะ (cm) ตรง ๆ
- US (fitted) = เส้นรอบศีรษะ (cm) ÷ 2.54 ÷ π แสดงเป็นเศษส่วน ⅛ นิ้ว (เช่น 58 cm → 7 ¼)

#### เสื้อผ้า — ฐาน: ตารางช่วง (Range Mapping) ไม่มีสูตร
- เทียบรอบอก (เสื้อ) / รอบเอว+สะโพก (กางเกง กระโปรง) กับช่วง [min, max) ของแต่ละมาตรฐาน (ช่วงเป็น half-open เพื่อไม่ให้ขอบซ้อนกัน)
- ถ้าค่าหลายจุดชี้คนละไซส์ (เช่น รอบอกชี้ M แต่รอบเอวชี้ L) ให้เลือกไซส์ใหญ่กว่า และบอกเหตุผลให้ผู้ใช้เห็น
- ค่าที่อยู่นอกตารางแสดง "ใหญ่/เล็กกว่าตาราง" ไม่เดา
- **กางเกงยีนส์:** ไซส์ = รอบเอว (cm) ÷ 2.54 ปัดเป็นเลขจำนวนเต็ม ใช้เป็นค่าประมาณและแสดงคำเตือนว่าป้ายไซส์ของกางเกงมักไม่ตรงขนาดจริง (vanity sizing); กางเกง/ยีนส์ผู้หญิงที่ใช้เบอร์ (US 0–16) ใช้ตาราง lookup
- ตัวเลขในตารางเป็นข้อมูลคงที่ในโค้ด (`data/`) ระบุแหล่งอ้างอิงในคอมเมนต์ ไม่ใช้ข้อมูลที่เดาขึ้นเอง

### ค. คำแนะนำการเผื่อไซส์ (Fit Guidance)
- ผู้ใช้เลือกสไตล์การใส่ต่อหมวด: **เสื้อผ้า** = พอดีตัว / ปกติ / หลวม (Oversize); **รองเท้า** = ปกติ / หน้าเท้ากว้าง (หรือเลือกเผื่อเพิ่ม)
- ระบบ "ขยับไซส์" ตามกฎคงที่และแสดงเหตุผล เช่น หน้าเท้ากว้าง → +0.5 ไซส์, Oversize → +1 ไซส์, พอดีตัว → ใช้ตามตาราง แล้วแสดงทั้ง "ไซส์ตามตัวเลข" และ "ไซส์ที่แนะนำ"
- ตัวเลขขยับ (กฎ) เก็บเป็นค่าคงที่ใน `constants.ts` ปรับแก้ภายหลังได้ ผลลัพธ์ทุกค่าเป็นคำแนะนำ ไม่ใช่ค่ารับประกัน
- **คู่มือวัดตัว:** ภาพประกอบ (SVG ไอคอนวาดเอง ไม่เพิ่มไลบรารี) + ขั้นตอนภาษาไทยต่อช่อง เช่น วางเท้าบนกระดาษแล้วขีดเส้นจากปลายส้นถึงปลายนิ้วที่ยาวที่สุด, วัดตอนเย็นเพราะเท้าขยายที่สุด, วัดเท้าทั้งสองข้างแล้วใช้ข้างที่ใหญ่กว่า แสดงใน Modal จากไอคอนข้างช่องกรอก

### ง. บันทึกไซส์ที่เคยใส่ได้จริง (Fit History)
- จดบันทึกต่อโปรไฟล์: แบรนด์, สินค้า/รุ่น (ไม่บังคับ), ไซส์ที่ใส่ (ข้อความ เช่น "US 9"), ความรู้สึก (พอดี / คับ / หลวม), หมายเหตุ
- เพิ่ม แก้ไข ลบ (มี Confirmation Dialog) ค้น/กรองตามแบรนด์ได้ เรียงล่าสุดก่อน
- ใช้อ้างอิงเอง ไม่เชื่อมกับตัวแปลง (ไม่ปรับผลคำนวณอัตโนมัติ)

### ทั่วไป
- Loading, Error+retry, Empty State, Toast ตามกฎกลาง; ข้อความ UI ทั้งหมดเป็นภาษาไทย; ปุ่มเป็นไอคอน + Tooltip + aria-label
- หน้าแบ่งเป็นแท็บ: **ตัวแปลง** (หน้าแรก), **โปรไฟล์**, **จดไซส์** (เส้นทางย่อย `/size-converter/...` แบบเดียวกับ finance/calorie)
- เมนูตัวแปลงใช้งานได้แม้ยังไม่มีโปรไฟล์ (กรอกค่าชั่วคราวได้) แต่โปรไฟล์/จดไซส์ต้องใช้ DB

## Database
ตาราง `size_profiles` (+ คอลัมน์มาตรฐานตาม CLAUDE.md ข้อ 6)

| Field | Type | Rule |
|---|---|---|
| name | text | NOT NULL, CHECK 1–50 ตัวอักษร, UNIQUE (user_id, lower(name)) |
| demographic | text | NOT NULL, CHECK IN ('men','women','kids') |
| is_self | boolean | NOT NULL DEFAULT false, ตั้ง "ฉัน" ได้ 1 โปรไฟล์ต่อผู้ใช้ (partial unique index) |
| height_cm, foot_length_cm, foot_width_cm, chest_cm, waist_cm, hip_cm, head_cm | numeric(5,1) | NULL ได้, CHECK ช่วงตามตาราง Validation |
| finger_circumference_mm | numeric(5,1) | NULL ได้, CHECK 30–100 |
| unit_pref | text | NOT NULL DEFAULT 'cm', CHECK IN ('cm','inch') (ต่อโปรไฟล์) |

ตาราง `size_notes` (+ คอลัมน์มาตรฐาน)

| Field | Type | Rule |
|---|---|---|
| profile_id | uuid | NOT NULL, FK → size_profiles(id) ON DELETE CASCADE (composite FK กับ user_id ตามแบบ finance) |
| brand | text | NOT NULL, CHECK 1–50 |
| product | text | NULL ได้, CHECK ≤ 100 |
| size_label | text | NOT NULL, CHECK 1–30 |
| fit | text | NOT NULL DEFAULT 'good', CHECK IN ('good','tight','loose') |
| note | text | NULL ได้, CHECK ≤ 500 |

Index: `user_id`; `size_notes(profile_id, created_at desc)`; `size_notes(user_id, lower(brand))`
Migration: ไฟล์ใหม่ `supabase/migrations/<timestamp>_size_converter.sql` ไม่แก้ไฟล์เดิม RLS 4 policy ต่อตาราง

## Open Questions
1. **ฐานข้อมูลแบรนด์ (Nike/Adidas/Zara/Uniqlo)** — ผมไม่มีแหล่งข้อมูลที่เชื่อถือได้ และข้อมูลแบรนด์เปลี่ยนตามรุ่น ข้อเสนอ: v1 **ไม่ทำฐานข้อมูลแบรนด์** ใช้ "จดไซส์ที่เคยใส่ได้จริง" (ข้อ ง) แทน แล้วเพิ่มตารางแบรนด์ใน Phase แยกเมื่อคุณมีแหล่งข้อมูลหรือยอมให้ผมค้นจากหน้า size chart ทางการของแต่ละแบรนด์ทีละรายการ
2. **ตารางเสื้อผ้า/กางเกง/กระโปรง** — ต้องมีตัวเลขช่วงจริง ข้อเสนอ: v1 ทำเสื้อและกางเกงของ ผู้ชาย/ผู้หญิง ตามตารางมาตรฐานกลางที่หาแหล่งอ้างอิงได้ (ผมจะค้นและระบุแหล่ง) และติดป้าย "ค่าประมาณ" ส่วนกระโปรงขอตัดออกจาก v1 ถ้าหาแหล่งไม่ได้ ตกลงไหม
3. **เด็ก** — ตารางรองเท้า/เสื้อเด็กต้องแบ่งตามอายุ/ความสูง ข้อเสนอ: v1 รองเท้าเด็กใช้ตาราง lookup ตามความยาวเท้า (US/UK/EU), เสื้อเด็กใช้ตามความสูง; หรือเลื่อนหมวดเด็กไป Phase ถัดไป เลือกอย่างไร
4. **Widget/Quick Overlay** — เว็บแอปซ้อนหน้าต่างทับแอปช้อปปิ้งอื่นไม่ได้ ข้อเสนอ: ทำเป็น "หน้าไซส์ของฉัน" แบบย่อ (การ์ดไซส์ทุกหมวดของโปรไฟล์ที่เลือกในหน้าเดียว ใช้บนมือถือข้างแอปอื่นด้วย split-screen/เปิดแท็บค้างไว้) ตกลงไหม
5. **เผยแพร่เป็นของใคร** — โปรไฟล์ของคนอื่นเก็บ "ข้อมูลร่างกายของบุคคลอื่น" ไว้ใน DB ของคุณเอง (ผูกกับ user_id ของคุณ ไม่แชร์) ยอมรับตามนี้ไหม
6. **คู่มือวัดตัวแบบภาพ** — ข้อเสนอ: SVG เส้นง่าย ๆ วาดเองตามจุดวัดแต่ละช่อง (ไม่เพิ่มไลบรารี) ถ้าต้องการภาพถ่าย/อนิเมชันต้องหาแหล่งภาพเพิ่ม
7. **รอบนิ้วหรือเส้นผ่านศูนย์กลาง** — ให้ผู้ใช้กรอกได้ทั้งสอง แต่ DB เก็บเฉพาะรอบนิ้ว (mm) ตกลงไหม

## Out of Scope
- ฐานข้อมูลตารางไซส์เฉพาะแบรนด์ (ถ้าตอบข้อ 1 ตามข้อเสนอ)
- Widget/Overlay ซ้อนบนแอปอื่นจริง ๆ (ทำไม่ได้ในเว็บ)
