# Feature: Expiry & Maintenance Tracker (กันลืม — ชื่อเมนูรอยืนยัน)

- **ID:** `expiry-tracker`
- **Route:** `/expiry-tracker`
- **Folder:** `src/features/expiry-tracker/`
- **Status:** In scope (Phase 11) — **ร่าง spec รอผู้ใช้ตอบ Open Questions และยืนยัน** (2026-11-16)

## Overview
ระบบจดเรื่องจุกจิกแต่สำคัญที่ผู้ใช้มักลืม เช่น เอกสารใกล้หมดอายุ (บัตร พาสปอร์ต ใบขับขี่) พรบ./ประกันรถ ล้างแอร์ เปลี่ยนไส้กรองน้ำ และค่าสมาชิกรายเดือน/รายปี
กรอกครั้งเดียว ระบบคำนวณวันครบกำหนดถัดไปให้ แสดงความเร่งด่วนเป็นสี สรุปค่าใช้จ่ายเดือนหน้า และเก็บประวัติเมื่อกด "ทำแล้ว"

หมายเหตุ: ฟีเจอร์นี้ครอบคลุมหมวด "Subscription" ที่เคยอยู่ใน Feature Index เป็น Future จึงรวมเข้าด้วยกัน (ไม่สร้างโมดูล Subscription แยก)

## Scope แบ่งเป็นรอบ
ข้อเสนอเดิมใหญ่และบางข้อเกินที่ Stack ปัจจุบันทำได้ตรง ๆ จึงแบ่งเป็นรอบ เพื่อให้ได้ของที่ใช้งานได้จริงก่อน

## Requirements

### หน้าจอ
- **หน้ารายการ (Dashboard):** แถบสรุปด้านบน (จำนวนเลยกำหนด / ใกล้ถึง / ค่าใช้จ่ายเดือนหน้า) + รายการเรียงตามวันครบกำหนดใกล้สุดก่อน กรองตามหมวดได้
- **เพิ่ม/แก้ไขรายการ:** ฟอร์มใน Modal ช่องกรอกเปลี่ยนตามหมวด
- **ประวัติ:** ดูประวัติของรายการนั้น ๆ (วันที่ทำ ค่าใช้จ่าย ผู้ให้บริการ เบอร์โทร หมายเหตุ)

### หมวดหมู่ตั้งต้น (ค่าคงที่ ไม่ใช่ตารางที่ผู้ใช้แก้)
| หมวด (`category`) | ชื่อแสดง | ตัวอย่าง | ช่องเฉพาะหมวด |
|---|---|---|---|
| `document` | เอกสารราชการ | บัตรประชาชน พาสปอร์ต ใบขับขี่ | - |
| `vehicle` | ยานพาหนะ | พรบ. ประกัน ถ่ายน้ำมันเครื่อง | เลขไมล์ (ตามระยะทาง) |
| `home` | ของใช้ในบ้าน | ล้างแอร์ ไส้กรองน้ำ ยาสามัญ | - |
| `subscription` | สมาชิก/ค่าบริการ | แอปสตรีมมิง คลาวด์ | ราคา, รอบตัดเงิน |
| `other` | อื่น ๆ | | - |

### ข้อมูลของรายการ
- ชื่อรายการ (จำเป็น), หมวด, วันครบกำหนด (จำเป็น), หมายเหตุ
- ค่าใช้จ่ายโดยประมาณ/ราคา (ไม่บังคับ) ใช้รวมในสรุปเดือนหน้า
- รอบทำซ้ำ (ไม่บังคับ): ทุก N วัน/เดือน/ปี; ไม่ตั้ง = ครั้งเดียว
- เตือนล่วงหน้าได้หลายระดับ (เลือกจำนวนวัน เช่น 180, 90, 30, 7, 3, 1) มีค่าแนะนำตามหมวด
- ผู้ให้บริการ/ช่าง: ชื่อ, เบอร์โทร (ไม่บังคับ)
- ตามระยะทาง/การใช้งาน (ไม่บังคับ): หน่วย (เช่น กม.), ทุกกี่หน่วย, ค่าที่ทำครั้งล่าสุด, ค่าปัจจุบัน (ผู้ใช้อัปเดตเอง) — ครบกำหนดเมื่อ "ถึงวันที่" **หรือ** "ถึงระยะ" อย่างใดอย่างหนึ่งก่อน

### สถานะความเร่งด่วน (คำนวณฝั่ง Client จากวันที่ ไม่เก็บใน DB)
- **แดง:** เลยกำหนด หรือเหลือน้อยกว่า 7 วัน (หรือถึงระยะที่กำหนดแล้ว)
- **เหลือง:** เหลือ 7–30 วัน
- **เขียว:** เหลือมากกว่า 30 วัน
- ใช้สีโทนหม่นและต้องมีข้อความกำกับ ไม่พึ่งสีอย่างเดียว (เหมือนป้าย "คุ้มที่สุด" ของ Unit Price) และต้องอ่านได้ทั้งโหมดสว่าง/มืด
- ขอบเขตวันเป็นค่าคงที่ใน `constants.ts`

### ปุ่ม "ทำแล้ว" (ต่ออายุ/ซ่อมบำรุงแล้ว)
- เปิด Modal ยืนยัน: วันที่ทำ (เริ่มต้นวันนี้), ค่าใช้จ่ายจริง, ผู้ให้บริการ/เบอร์โทร, หมายเหตุ
- บันทึกลงประวัติ แล้ว: ถ้ามีรอบทำซ้ำ → วันครบกำหนดใหม่ = **วันที่ทำ + รอบ**; ถ้าไม่มีรอบ → ถามว่าจะตั้งวันครบกำหนดใหม่เองหรือเก็บรายการ (Q3)
- กฎ "วันที่ + N เดือน" ใช้วันสิ้นเดือนเมื่อวันนั้นไม่มีในเดือนปลายทาง (เช่น 31 ม.ค. + 1 เดือน = 28/29 ก.พ.)

### สรุปค่าใช้จ่ายเดือนหน้า
- รวมค่าใช้จ่ายของรายการที่วันครบกำหนด (รวมรอบที่จะซ้ำในช่วงนั้น) ตกอยู่ในเดือนปฏิทินถัดไป
- รายการที่ไม่ได้ใส่ค่าใช้จ่ายไม่นับ และบอกจำนวนที่ไม่มีราคา

### ทั่วไป
- มี Loading, Error, Empty State และ Toast ตามกฎกลาง; การลบมี Confirmation Dialog
- ลบรายการ = ลบประวัติของรายการนั้นด้วย (บอกในข้อความยืนยัน)
- ข้อความที่ผู้ใช้เห็นเป็นภาษาไทยทั้งหมด

## Database
ผู้ใช้ Anonymous: ข้อมูลผูกกับ `user_id` ตามกฎกลาง และเปิด RLS `auth.uid() = user_id` ทุกตาราง

### ตาราง `reminder_items` (+ คอลัมน์มาตรฐานตาม CLAUDE.md ข้อ 6)
| Field | Type | Rule |
|---|---|---|
| category | text | NOT NULL, CHECK in (`document`,`vehicle`,`home`,`subscription`,`other`) |
| name | text | NOT NULL, ไม่ว่าง, ≤ 100 ตัวอักษร |
| due_date | date | NOT NULL |
| repeat_every | int | NULL ได้, CHECK > 0 |
| repeat_unit | text | NULL ได้, CHECK in (`day`,`month`,`year`); ต้องมีพร้อมกับ `repeat_every` (CHECK ทั้งคู่ null หรือทั้งคู่มีค่า) |
| remind_before_days | int[] | NOT NULL default `{}`, ค่าแต่ละตัว 0–730 (บังคับด้วย CHECK) |
| cost | numeric(12,2) | NULL ได้, CHECK >= 0 |
| provider_name | text | NULL ได้, ≤ 100 |
| provider_phone | text | NULL ได้, ≤ 30 |
| note | text | NULL ได้, ≤ 500 |
| usage_unit | text | NULL ได้, ≤ 20 |
| usage_interval | numeric(10,1) | NULL ได้, CHECK > 0 |
| usage_last_done | numeric(10,1) | NULL ได้, CHECK >= 0 |
| usage_current | numeric(10,1) | NULL ได้, CHECK >= 0 |

CHECK เพิ่ม: ฟิลด์ `usage_*` ต้องกรอกครบชุดหรือไม่กรอกเลย

### ตาราง `reminder_logs` (ประวัติ — เก็บสำเนา ณ ตอนทำ เหมือน `food_entries`)
| Field | Type | Rule |
|---|---|---|
| item_id | uuid | FK → `reminder_items` ON DELETE CASCADE (ลบรายการ = ลบประวัติ) |
| item_name | text | NOT NULL, สำเนาชื่อ ณ ตอนทำ |
| done_on | date | NOT NULL |
| cost | numeric(12,2) | NULL ได้, CHECK >= 0 |
| provider_name / provider_phone | text | NULL ได้ |
| note | text | NULL ได้, ≤ 500 |
| usage_value | numeric(10,1) | NULL ได้ ค่าระยะ ณ ตอนทำ |

Index: `user_id`, (`user_id`,`due_date`) บน items, (`item_id`,`done_on`) บน logs
Migration: `supabase/migrations/<timestamp>_expiry_tracker.sql` (ไฟล์ใหม่ ไม่แก้ไฟล์เดิม)

บันทึก "ทำแล้ว" ต้องเขียน 2 อย่าง (เพิ่ม log + เลื่อน due_date) ให้เป็น **RPC เดียวใน DB** (security invoker, ทำภายใต้ RLS) เพื่อไม่ให้ทำสำเร็จครึ่งเดียว

## Open Questions
1. **ชื่อเมนู:** ตามธีมที่ตั้งไว้ (วันนี้ทำอะไรดี / สับสนช่วยหน่อย / เงินฉันไปไหน / ผอมไปด้วยกัน / อันไหนถูกกว่า บอกมา) เสนอ "**อย่าลืมนะ**" หรือ "**ใกล้หมดอายุแล้วนะ**" — ใช้ชื่อไหน? และ path `/expiry-tracker` ใช้ได้ไหม
2. **การเตือน:** v1 เตือนเฉพาะ **ในแอป** (แถบสรุป + สีบนรายการ ต้องเปิดแอปจึงเห็น) ยอมรับได้ไหม? หรืออยากได้การเตือนนอกแอป (ต้องเพิ่มเซิร์ฟเวอร์/Cron และอาจเพิ่มไลบรารี ควรเป็นเฟสแยก)
3. **ปุ่ม "ทำแล้ว" กับรายการที่ไม่มีรอบทำซ้ำ:** ให้ (ก) ถามวันครบกำหนดใหม่, หรือ (ข) ย้ายไปสถานะ "เสร็จแล้ว/เก็บถาวร" ซ่อนจากรายการหลัก?
4. **แนบไฟล์/รูป:** (ก) ไม่ทำใน v1, (ข) ทำใน v1 ด้วย Supabase Storage (ประเภท jpg/png/pdf, จำกัดขนาดต่อไฟล์ และจำนวนต่อรายการ — ต้องกำหนดตัวเลข) ผมแนะนำ (ก) แล้วทำเป็น Phase แยก เพราะเป็นข้อมูลบัตร/พาสปอร์ต ต้องออกแบบ bucket และ policy ให้รัดกุม
5. **ล็อกด้วยชีวมิติ:** ยอมรับให้เลื่อนไปเฟสหลัง (ต้องมี Login จริงก่อน) ไหม ผู้ใช้ Anonymous ถ้าเปลี่ยนเบราว์เซอร์ก็เสียตัวตนอยู่แล้ว
6. **ผู้ใช้ Anonymous:** ข้อมูลสำคัญ (วันหมดอายุ เบอร์ช่าง) จะหายถ้าล้างข้อมูลเบราว์เซอร์/เปลี่ยนเครื่อง จนกว่าจะมี Login จริง ยอมรับข้อจำกัดนี้ไหม
7. **เตือนล่วงหน้า:** ให้ผู้ใช้เลือกจำนวนวันเองอิสระ หรือเลือกจากชุดสำเร็จรูปตามหมวด (เช่น เอกสาร 180/90/30, สมาชิก 3/1)?
8. **ค่าใช้จ่ายเดือนหน้า:** รวมเฉพาะรายการที่ครบกำหนดในเดือนปฏิทินถัดไป ตามที่เขียนไว้ ใช่ไหม หรืออยากได้ "30 วันข้างหน้า"
9. **เลขไมล์:** เป็นหน่วย "กม." อย่างเดียวพอไหม หรืออยากให้พิมพ์หน่วยเองได้ (spec ตอนนี้ให้พิมพ์เอง)
10. **เชื่อมกับรายรับ-รายจ่าย:** ไม่เชื่อมใน v1 (ค่าใช้จ่ายตอน "ทำแล้ว" ไม่ถูกบันทึกเป็นรายจ่ายอัตโนมัติ) ใช่ไหม
