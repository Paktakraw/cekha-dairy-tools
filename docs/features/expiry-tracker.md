# Feature: Expiry & Maintenance Tracker (อย่าลืมฉัน)

- **ID:** `expiry-tracker`
- **Route:** `/expiry-tracker`
- **Folder:** `src/features/expiry-tracker/`
- **Status:** In scope (Phase 11) — spec ยืนยันแล้ว (2026-11-16)
- **ชื่อเมนู:** อย่าลืมฉัน · **Icon:** `CalendarClock`

## Overview
ระบบจดเรื่องจุกจิกแต่สำคัญที่ผู้ใช้มักลืม เช่น เอกสารใกล้หมดอายุ (บัตร พาสปอร์ต ใบขับขี่) พรบ./ประกันรถ ล้างแอร์ เปลี่ยนไส้กรองน้ำ และค่าสมาชิกรายเดือน/รายปี
กรอกครั้งเดียว ระบบคำนวณวันครบกำหนดถัดไปให้ แสดงความเร่งด่วนเป็นสี สรุปค่าใช้จ่ายเดือนหน้า และเก็บประวัติเมื่อกด "ทำแล้ว"

หมายเหตุ: ฟีเจอร์นี้ครอบคลุมหมวด "Subscription" ที่เคยอยู่ใน Feature Index เป็น Future จึงรวมเข้าด้วยกัน (ไม่สร้างโมดูล Subscription แยก)

## Requirements

### หน้าจอ
- **หน้ารายการ (Dashboard):** แถบสรุปด้านบน (จำนวนเลยกำหนด / ถึงเกณฑ์เตือน / ค่าใช้จ่ายเดือนหน้า) + รายการเรียงตามวันครบกำหนดใกล้สุดก่อน (รายการที่ถึงระยะแล้วขึ้นก่อน) มี 2 แท็บ: **ใช้งานอยู่** / **เก็บถาวร** ไม่มีตัวกรองหมวดหมู่ (ผู้ใช้ขอเอาออก 2026-11-16)
- **การเพิ่มรายการ:** ทำได้จากปุ่ม "เพิ่มรายการ" (ไอคอน +) ด้านบนปุ่มเดียว ไม่มีปุ่มเพิ่มซ้ำใน Empty State
- **เพิ่ม/แก้ไขรายการ:** ฟอร์มใน Modal ช่องกรอกเปลี่ยนตามหมวด
- **ประวัติ:** เปิดเป็น Modal จากการ์ดรายการ แสดงวันที่ทำ ค่าใช้จ่าย ผู้ให้บริการ เบอร์โทร หมายเหตุ (ใหม่ไปเก่า)

### หมวดหมู่ตั้งต้น (ค่าคงที่ ไม่ใช่ตารางที่ผู้ใช้แก้)
| หมวด (`category`) | ชื่อแสดง | ตัวอย่าง | ช่องเฉพาะหมวด |
|---|---|---|---|
| `document` | เอกสารราชการ | บัตรประชาชน พาสปอร์ต ใบขับขี่ | - |
| `vehicle` | ยานพาหนะ | พรบ. ประกัน ถ่ายน้ำมันเครื่อง | เลขไมล์ (ตามระยะทาง) |
| `home` | ของใช้ในบ้าน | ล้างแอร์ ไส้กรองน้ำ ยาสามัญ | - |
| `medical` | รักษาพยาบาล | นัดหมอ วัคซีน ตรวจสุขภาพ ประกันสุขภาพ | โรงพยาบาล/แพทย์ + เบอร์โทร |
| `subscription` | สมาชิก/ค่าบริการ | แอปสตรีมมิง คลาวด์ | ราคา, รอบตัดเงิน |
| `other` | อื่น ๆ | | - |

### ข้อมูลของรายการ
- ชื่อรายการ (จำเป็น), หมวด, วันครบกำหนด (จำเป็น), หมายเหตุ
- ค่าใช้จ่ายโดยประมาณ/ราคา (ไม่บังคับ) ใช้รวมในสรุปเดือนหน้า
- รอบทำซ้ำ (ไม่บังคับ): ทุก N วัน/เดือน/ปี; ไม่ตั้ง = ครั้งเดียว
- เตือนล่วงหน้า **เลือกได้ 1 ระดับ** (ผู้ใช้ขอ 2026-11-17) เลือกได้ **2 แบบ**: (ก) กดปุ่มจากชุดสำเร็จรูปของหมวด (ข) พิมพ์จำนวนวันเอง 0–730 แล้วกด + ; กดอันใหม่ = แทนที่, กดอันที่เลือกอยู่ซ้ำ = ไม่ตั้งเตือน (DB ยังเป็นอาร์เรย์ได้หลายระดับ เผื่ออนาคตและรายการเก่า ไม่ต้องแก้ migration); ถึงเกณฑ์เตือน = จำนวนวันที่เหลือ ≤ ระดับที่มากที่สุดที่ตั้งไว้ (รวมเลยกำหนด) การ์ดแสดงป้ายเตือนในแอป; ในฟอร์มแสดง **วันที่เตือนที่คำนวณได้** (วันครบกำหนด − N วัน เป็นวัน เดือนเต็ม ปี พ.ศ.) ของทุกระดับที่เลือก และพรีวิวทันทีขณะพิมพ์จำนวนวันเอง (ต้องเลือกวันครบกำหนดก่อน; วันที่ผ่านมาแล้วมีป้ายกำกับ)
- **วันครบกำหนด:** เลือกจากปฏิทิน หรือพิมพ์ "อีกกี่วัน" (0–36,500, นับจากวันนี้) แล้วระบบเติมช่องวันครบกำหนดให้ และแสดง "ตรงกับวันที่ …" แบบเต็ม; เลือกวันจากปฏิทินแล้วช่อง "อีกกี่วัน" เติมตามให้ (วันที่ผ่านมาแล้ว = เว้นว่าง)
- ชุดสำเร็จรูป: เอกสาร 180/90/30, ยานพาหนะ 30/7, ของใช้ในบ้าน 7/1, รักษาพยาบาล 30/7/1, สมาชิก 3/1, อื่น ๆ 7/1
- ผู้ให้บริการ/ช่าง: ชื่อ, เบอร์โทร (ไม่บังคับ)
- ตามระยะทาง/การใช้งาน (ไม่บังคับ): หน่วยพิมพ์เองได้ (เช่น กม.), ทุกกี่หน่วย, ค่าที่ทำครั้งล่าสุด, ค่าปัจจุบัน (ผู้ใช้อัปเดตเอง) — ครบกำหนดเมื่อ "ถึงวันที่" **หรือ** "ถึงระยะ" อย่างใดอย่างหนึ่งก่อน

### สถานะความเร่งด่วน (คำนวณฝั่ง Client จากวันที่ ไม่เก็บใน DB)
- **แดง:** เลยกำหนด หรือเหลือน้อยกว่า 7 วัน (หรือถึงระยะที่กำหนดแล้ว)
- **เหลือง:** เหลือ 7–30 วัน
- **เขียว:** เหลือมากกว่า 30 วัน
- ใช้สีโทนหม่นและต้องมีข้อความกำกับ ไม่พึ่งสีอย่างเดียว (เหมือนป้าย "คุ้มที่สุด" ของ Unit Price) และต้องอ่านได้ทั้งโหมดสว่าง/มืด
- ขอบเขตวันเป็นค่าคงที่ใน `constants.ts`

### ปุ่ม "ทำแล้ว" (ต่ออายุ/ซ่อมบำรุงแล้ว)
- เปิด Modal ยืนยัน: วันที่ทำ (เริ่มต้นวันนี้), ค่าใช้จ่ายจริง, ผู้ให้บริการ/เบอร์โทร, หมายเหตุ, ค่าระยะ ณ ตอนนี้ (ถ้าตั้งตามระยะ)
- บันทึกลงประวัติ แล้ว: ถ้ามีรอบทำซ้ำ → วันครบกำหนดใหม่ = **วันที่ทำ + รอบ** (แก้ในช่องได้ก่อนบันทึก); ถ้าไม่มีรอบ → ช่อง "วันครบกำหนดครั้งถัดไป" ว่างไว้ได้: **กรอก = เลื่อนวันครบกำหนด, ไม่กรอก = เก็บถาวร** (ย้ายไปแท็บเก็บถาวร ยังดูประวัติได้)
- ถ้าตั้งตามระยะ: ค่าระยะที่ทำครั้งล่าสุด = ค่าระยะที่กรอก (ถ้าไม่กรอกใช้ค่าปัจจุบัน)
- กฎ "วันที่ + N เดือน" ใช้วันสิ้นเดือนเมื่อวันนั้นไม่มีในเดือนปลายทาง (เช่น 31 ม.ค. + 1 เดือน = 28/29 ก.พ.)

### สรุปค่าใช้จ่ายเดือนหน้า
- รวมค่าใช้จ่ายของรายการที่วันครบกำหนด (รวมรอบที่จะซ้ำในช่วงนั้น) ตกอยู่ในเดือนปฏิทินถัดไป
- รายการที่ไม่ได้ใส่ค่าใช้จ่ายไม่นับ และบอกจำนวนที่ไม่มีราคา

### ทั่วไป
- มี Loading, Error, Empty State และ Toast ตามกฎกลาง; การลบมี Confirmation Dialog
- ลบรายการ = ลบประวัติของรายการนั้นด้วย (บอกในข้อความยืนยัน)
- ข้อความที่ผู้ใช้เห็นเป็นภาษาไทยทั้งหมด

## Database
ผู้ใช้ Anonymous: ข้อมูลผูกกับ `user_id` ตามกฎกลาง และเปิด RLS `auth.uid() = user_id` ทุกตาราง

### ตาราง `reminder_items` (+ คอลัมน์มาตรฐานตาม CLAUDE.md ข้อ 6)
| Field | Type | Rule |
|---|---|---|
| archived_at | timestamptz | NULL = ใช้งานอยู่, มีค่า = เก็บถาวร |
| category | text | NOT NULL, CHECK in (`document`,`vehicle`,`home`,`medical`,`subscription`,`other`) (`medical` เพิ่มด้วย migration `20261116000200_expiry_tracker_medical.sql`) |
| name | text | NOT NULL, ไม่ว่าง, ≤ 100 ตัวอักษร |
| due_date | date | NOT NULL |

| remind_before_days | int[] | NOT NULL default `{}`, ค่าแต่ละตัว 0–730 (บังคับด้วย CHECK) |
| cost | numeric(12,2) | NULL ได้, CHECK >= 0 |
| provider_name | text | NULL ได้, ≤ 100 |
| provider_phone | text | NULL ได้, ≤ 30 |

| usage_unit | text | NULL ได้, ≤ 20 |

### ตาราง `reminder_logs` (ประวัติ — เก็บสำเนา ณ ตอนทำ เหมือน `food_entries`)
| Field | Type | Rule |
|---|---|---|
| item_id | uuid | FK → `reminder_items` ON DELETE CASCADE (ลบรายการ = ลบประวัติ) |
| item_name | text | NOT NULL, สำเนาชื่อ ณ ตอนทำ |
| done_on | date | NOT NULL |
| cost | numeric(12,2) | NULL ได้, CHECK >= 0 |
| provider_name / provider_phone | text | NULL ได้ |
| note | text | NULL ได้, ≤ 500 |
| usage_value | numeric(10,1) | NULL ได้ ค่าระยะ ณ ตอนทำ |

Index: `user_id`, (`user_id`,`due_date`) บน items, (`item_id`,`done_on`) บน logs
Migration: `supabase/migrations/<timestamp>_expiry_tracker.sql` (ไฟล์ใหม่ ไม่แก้ไฟล์เดิม)

บันทึก "ทำแล้ว" ต้องเขียน 2 อย่าง (เพิ่ม log + เลื่อน due_date หรือเก็บถาวร) ให้เป็น **RPC เดียวใน DB** `complete_reminder(...)` (security invoker, ทำภายใต้ RLS) เพื่อไม่ให้ทำสำเร็จครึ่งเดียว; วันครบกำหนดใหม่คำนวณฝั่ง Client (pure function) แล้วส่งเป็นพารามิเตอร์

### เตรียมรองรับแนบไฟล์ (ไม่ทำใน v1)
ไม่มีปุ่ม/ช่องอัปโหลดใน v1 (กฎ: ห้ามสร้าง UI ที่ไม่มี Function จริง) แต่โครงสร้างเผื่อไว้: ในอนาคตเพิ่มตาราง `reminder_attachments` (`item_id` FK, `storage_path`, ...) + Storage bucket ด้วย migration ใหม่ และเพิ่มส่วนแนบไฟล์ใน `ItemFormModal`/การ์ดโดยไม่ต้องแก้ตารางเดิม

## Decisions (ผู้ใช้ตอบ 2026-11-16)
1. ชื่อเมนู "อย่าลืมฉัน" path `/expiry-tracker`
2. เตือนเฉพาะในแอป
3. "ทำแล้ว" กับรายการไม่มีรอบ: ถามวันครบกำหนดใหม่ มี = เลื่อน, ไม่มี = เก็บถาวร
4. แนบไฟล์: เตรียมรองรับในอนาคต (ตีความว่าเผื่อโครงสร้าง ไม่ทำ UI อัปโหลดใน v1)
5. ยังไม่ทำล็อกชีวมิติ
6. ยอมรับข้อจำกัดผู้ใช้ Anonymous (ข้อมูลหายถ้าล้างเบราว์เซอร์/เปลี่ยนเครื่องจนกว่าจะมี Login จริง)
7. เตือนล่วงหน้า: เลือกจากชุดสำเร็จรูปและพิมพ์เองได้ทั้ง 2 แบบ
8. สรุปค่าใช้จ่าย: เดือนปฏิทินถัดไป
9. หน่วยระยะพิมพ์เองได้
10. ยังไม่เชื่อมกับรายรับ-รายจ่าย

## Out of Scope (v1)
- การเตือนนอกแอป (Push / LINE / อีเมล / ปฏิทินภายนอก)
- ล็อกด้วยลายนิ้วมือ/ใบหน้า (WebAuthn)
- แนบไฟล์/รูป
- การแชร์รายการกับผู้อื่น, OCR อ่านวันหมดอายุจากรูป
- เชื่อมรายการกับโมดูลรายรับ-รายจ่ายอัตโนมัติ
