# Feature: ภาพรวมวันนี้ (Today Overview)

- **ID:** `dashboard` (ส่วนของหน้า Portal ไม่ใช่ฟีเจอร์ในเมนู จึงไม่มี path ของตัวเอง ไม่ลงทะเบียนเป็นฟีเจอร์ใน Registry)
- **Route:** `/` (หน้า Portal เดิม)
- **Folder:** `src/pages/` (หน้า Portal), `src/shared/components/dashboard/` (กรอบการ์ด), การ์ดของแต่ละฟีเจอร์อยู่ที่ `src/features/<feature>/widgets/`
- **Status:** In scope (Phase 15) — spec ยืนยันแล้ว (2026-11-24) ผู้ใช้ตอบ Open Questions ทุกข้อตามที่เสนอ

## Overview
เมื่อเปิดแอป ผู้ใช้เห็น "ภาพรวมวันนี้" เหนือการ์ดเครื่องมือเดิม เป็นการ์ดสรุปสั้น ๆ ว่าวันนี้มีอะไรต้องสนใจ เช่น งานค้างกี่งาน มีเอกสารเลยกำหนดไหม ใช้เงินไปเท่าไร กินไปกี่แคลอรี่ เช็กอินอารมณ์แล้วหรือยัง กดการ์ดเพื่อไปยังเครื่องมือนั้น
เป้าหมายคือให้เปิดแอปครั้งเดียวเห็นภาพรวม และเป็นฐานสำหรับการเชื่อมข้อมูลข้ามเครื่องมือในอนาคต

**เวอร์ชันแรก (v1) อ่านข้อมูลอย่างเดียว** ไม่แก้ข้อมูลข้ามฟีเจอร์ ไม่เพิ่มตารางและไม่มี migration

## แนวทางที่เสนอ (ไม่ผิดกฎ 4.1)
กฎ 4.1 ห้ามฟีเจอร์ import โค้ดภายในของฟีเจอร์อื่น และต้องเพิ่มฟีเจอร์ได้โดยไม่แก้ฟีเจอร์เดิม จึงเสนอแบบ **"ฟีเจอร์ส่งการ์ดของตัวเองมาให้"**:

1. เพิ่มฟิลด์ `todayWidget` (ไม่บังคับ) ใน `FeatureConfig` (`src/shared/types/feature.ts`) เป็น React component ที่โหลดแบบ lazy
2. แต่ละฟีเจอร์ที่มีข้อมูลรายวันสร้างการ์ดของตัวเองในโฟลเดอร์ของตัวเอง โดยใช้ hook/service/utils ของตัวเอง แล้ว export ผ่าน `index.tsx`
3. หน้า Portal วนอ่าน Registry แล้วแสดงการ์ดของทุกฟีเจอร์ที่มี `todayWidget` เรียงตามลำดับใน Registry
4. หน้า Portal **ไม่รู้จักข้อมูลของฟีเจอร์ใดเลย** แค่ใส่กรอบ (หัวข้อ ไอคอน ลิงก์ไปฟีเจอร์ สถานะโหลด/ผิดพลาด)

ผลที่ได้: เพิ่มฟีเจอร์ใหม่ที่อยากมีการ์ด = เพิ่ม `todayWidget` ในฟีเจอร์นั้นที่เดียว ไม่ต้องแก้หน้า Portal หรือฟีเจอร์อื่น และไม่มีการ import ข้ามฟีเจอร์

> ทางเลือกที่ไม่เลือก: (ก) ให้หน้า Portal เรียก service ของทุกฟีเจอร์ตรง ๆ — ผิดกฎ 4.1 และต้องแก้หน้า Portal ทุกครั้งที่เพิ่มฟีเจอร์; (ข) สร้าง view/RPC ใน Supabase รวมข้อมูลทุกตาราง — ผูกฐานข้อมูลของทุกฟีเจอร์ไว้ด้วยกัน ต้องมี migration และแก้เมื่อฟีเจอร์ใดเปลี่ยน; จึงใช้แนวทางข้างบน

## Requirements

### หน้าจอ
- หัวข้อ **"ภาพรวมวันนี้"** พร้อมวันที่ปัจจุบันแบบเต็ม (ภาษาไทย) อยู่เหนือการ์ดเครื่องมือเดิม ส่วน "เลือกเครื่องมือที่ต้องการใช้งาน" และการ์ดเครื่องมือเดิมอยู่ต่อด้านล่างโดยไม่เปลี่ยน
- การ์ดภาพรวมวางเป็นตาราง **1 คอลัมน์บนมือถือ, 2 คอลัมน์บนแท็บเล็ต (≥ 768px), 3 คอลัมน์บนจอกว้าง (≥ 1024px)** ตามสไตล์มินิมอลเดิม (ขาว ดำ เทา, สีเขียว/แดงหม่นเฉพาะที่อนุญาตอยู่แล้ว)
- **ย่อ/ขยายได้** (เพิ่มตามคำขอผู้ใช้ 2026-11-24): ปุ่มลูกศรอยู่แถวเดียวกับวันที่ (วันที่ชิดซ้าย ลูกศรชิดขวา) พร้อม Tooltip/aria-label ("ขยาย/ย่อภาพรวมวันนี้") และ `aria-expanded`; **ค่าเริ่มต้นย่อไว้ทุกครั้งที่เปิดหน้า (ไม่จำสถานะ)** หัวข้อ "ภาพรวมวันนี้" และวันที่เห็นเสมอ; การ์ดเริ่มโหลดข้อมูลเมื่อกางครั้งแรก (ย่อไว้ไม่ยิงคำขอ) และย่อแล้วกางใหม่ไม่โหลดซ้ำ
- กดทั้งการ์ดเพื่อไปหน้าของฟีเจอร์นั้น (เป็นลิงก์ ไม่ใช่ปุ่มแก้ข้อมูล)
- ทุกการ์ดโหลดข้อมูล **แยกกัน** การ์ดหนึ่งล้มเหลวหรือช้า ไม่กระทบการ์ดอื่นและไม่กระทบการ์ดเครื่องมือด้านล่าง
- แต่ละการ์ดมี 3 สถานะของตัวเอง: กำลังโหลด (โครงเทา) · ผิดพลาด (ข้อความสั้น + ปุ่ม **ลองใหม่** ในการ์ด) · มีข้อมูล / ยังไม่มีข้อมูล
- ข้อมูลรีเฟรชเมื่อเข้าหน้า Portal ใหม่ (ไม่ต้อง Reload ทั้งหน้า ไม่ polling)
- ข้อความทั้งหมดเป็นภาษาไทย รองรับโหมดมืด และใช้ได้ทุกขนาดจอ

### การ์ดที่ทำใน v1
ทั้งหมดอ่านข้อมูลของ "วันนี้" ตามเวลาท้องถิ่นของผู้ใช้ (ไม่ใช่ UTC)

| ฟีเจอร์ | การ์ดแสดง | ถ้ายังไม่มีข้อมูล | กดแล้วไป |
|---|---|---|---|
| วันนี้ทำอะไรดี | จำนวนงานที่ **ยังไม่เสร็จ** (รอดำเนินการ + กำลังทำ) และจำนวนที่ทำเสร็จวันนี้ | "ยังไม่มีงานค้าง" | `/todo` |
| อย่าลืมฉัน | จำนวนที่ **เลยกำหนด** และ **ถึงเกณฑ์เตือน** + ชื่อรายการที่ใกล้ครบกำหนดที่สุด 1 รายการพร้อมสีสถานะและข้อความ "อีก N วัน" | "ไม่มีรายการใกล้ครบกำหนด" | `/expiry-tracker` |
| เงินฉันไปไหน | รายจ่ายวันนี้ และรายจ่ายเดือนนี้ (รายรับวันนี้แสดงเมื่อมี) | "วันนี้ยังไม่ได้จดรายการ" | `/finance/transactions` |
| ผอมไปด้วยกัน | แคลอรี่ที่กินวันนี้ เทียบกับ TDEE (ถ้าคำนวณไว้แล้ว) | "วันนี้ยังไม่ได้จดอาหาร" (ถ้ายังไม่มี TDEE มีลิงก์ไปคำนวณ) | `/calorie/food` |
| ตัวฉันวันนี้ | ถ้าเช็กอินแล้ว: อิโมจิ + ชื่ออารมณ์ของวันนี้; ถ้ายัง: "วันนี้ยังไม่ได้เช็กอิน" | (คือกรณียังไม่เช็กอิน) | `/mood/today` |

ฟีเจอร์ **สับสนช่วยหน่อย, อันไหนถูกกว่า บอกมา, ไซส์ไหนคือฉัน ไม่มีการ์ด** เพราะไม่มีข้อมูลรายวันที่ควรสรุป (ยังคงมีการ์ดเครื่องมือเดิมด้านล่าง)

### กฎของการ์ด
- แสดงเฉพาะข้อมูลของผู้ใช้เอง (ใช้ service ของแต่ละฟีเจอร์ที่ผ่าน RLS เดิม)
- **การ์ดไม่แสดงข้อความของผู้ใช้ที่อาจอ่อนไหว:** ตัวฉันวันนี้แสดงเฉพาะอิโมจิ/ชื่ออารมณ์ ไม่แสดงแท็กและข้อความสั้น; เงินแสดงเฉพาะยอดรวม ไม่แสดงคำอธิบายรายการ
- ตัวเลขเงินแสดงแบบ ฿1,000.00 ตามที่ใช้อยู่แล้ว
- ไม่มีปุ่มแก้ไข/ลบ/เพิ่มในการ์ด (v1) กดแล้วไปทำที่หน้าของฟีเจอร์

### เชิงเทคนิค
- Layering เดิม: การ์ด (UI) → hook ของฟีเจอร์ → service ของฟีเจอร์ → Supabase; การ์ดไม่เรียก Supabase ตรง
- แต่ละฟีเจอร์เพิ่ม **ฟังก์ชัน service แบบเบา** สำหรับการ์ดของตัวเอง (เช่น นับงานค้าง, รายการที่ใกล้ครบกำหนดที่สุด, ยอดรายจ่ายวันนี้/เดือนนี้) ใช้ฟังก์ชันที่มีอยู่ก่อนถ้าพอ ไม่แก้พฤติกรรมของหน้าเดิม
- คำนวณ/จัดรูปตัวเลขเป็น **pure function** ใน `utils/` ของฟีเจอร์นั้นและมีเทสต์ใน `tests/` (เช่น นับงานค้าง, เลือกรายการใกล้ครบกำหนด, แคลอรี่วันนี้เทียบ TDEE, ยอดรายจ่ายวันนี้/เดือนนี้) โดย **ใช้ utils ที่มีอยู่แล้วซ้ำ** (`urgency`, `reminders`, `summarizeDay`, `summarize` ฯลฯ) ไม่เขียนสูตรซ้ำ
- การ์ดโหลดแบบ lazy (เหมือนหน้าของฟีเจอร์) เพื่อไม่ถ่วงการโหลดหน้าแรก
- วันที่ "วันนี้" ใช้ตัวช่วยวันที่ท้องถิ่นเดิมของโปรเจกต์ ไม่ใช้ `toISOString()`
- คำขอข้อมูลของแต่ละการ์ดรันขนานกัน (ไม่รอกัน) ถ้าผู้ใช้ออกจากหน้าก่อนโหลดเสร็จ ผลที่มาช้าต้องไม่เขียนทับ state (ใช้รูปแบบ ignore flag เหมือน hook เดิม)
- ผู้ใช้ที่ไม่มีข้อมูลเลยในทุกฟีเจอร์ (ผู้ใช้ใหม่): แสดงการ์ดแบบ "ยังไม่มีข้อมูล" ตามตาราง ไม่ซ่อนส่วนภาพรวม

## Database
ไม่มีตารางและไม่มี migration ในเวอร์ชันนี้ (อ่านจากตารางเดิมของแต่ละฟีเจอร์ผ่าน RLS เดิม)

## Suggested Components
- `src/shared/types/feature.ts`: เพิ่ม `todayWidget?: LazyExoticComponent<ComponentType>`
- `src/shared/components/dashboard/`: `TodayOverview` (อ่าน Registry แล้ววางการ์ด), `WidgetFrame` (กรอบ/ลิงก์/Loading/Error+ลองใหม่/Empty ที่การ์ดทุกใบใช้ร่วมกัน)
- `src/features/<feature>/widgets/<Feature>TodayWidget.tsx` (todo, expiry-tracker, finance, calorie, mood) + hook ของการ์ด + ฟังก์ชัน service เบา
- `src/features/<feature>/utils/` ฟังก์ชัน pure ที่ต้องเพิ่ม (ถ้ายังไม่มี) + เทสต์ใน `tests/`
- `src/pages/PortalHomePage.tsx`: เพิ่มส่วน `TodayOverview` เหนือการ์ดเครื่องมือ

## Decisions (ผู้ใช้ตอบ Open Questions เมื่อ 2026-11-24: ทำตามที่เสนอทุกข้อ)
คำตอบที่ยืนยันอยู่ในวงเล็บ

1. **ตำแหน่ง:** ให้ภาพรวมอยู่บนหน้า Portal เดิมเหนือการ์ดเครื่องมือ หรือทำเป็นหน้าแยก (เช่น `/today`) และเพิ่มเมนู? (แนะนำ: บนหน้า Portal เดิม ไม่เพิ่มเมนู ไม่เพิ่ม route)
2. **การ์ดที่ยังไม่มีข้อมูล:** แสดงข้อความชวนไปจดข้อมูล หรือซ่อนการ์ดนั้น? (แนะนำ: แสดง เพราะชวนให้ใช้ และผู้ใช้เห็นว่ามีเครื่องมือนี้)
3. **ความเป็นส่วนตัวบนหน้าแรก:** อนุญาตให้หน้าแรกแสดงอารมณ์วันนี้และตัวเลขรายจ่าย/แคลอรี่เลยไหม หรือให้มีปุ่ม "ซ่อนตัวเลข" (ไอคอนตา) ที่ผู้ใช้กดซ่อนเอง? (แนะนำ: v1 แสดงตามปกติ ตัดปุ่มซ่อนไว้ก่อน แต่ไม่แสดงแท็ก/ข้อความอารมณ์; ถ้าต้องการปุ่มซ่อนให้เป็น Phase ต่อไป เพราะต้องเก็บค่าตั้งใน `user_preferences`)
4. **อารมณ์วันนี้:** เมื่อผู้ใช้เลือก 😩/😭 ให้การ์ดแสดงอะไรพิเศษไหม? (แนะนำ: ไม่ มีเพียงอิโมจิและชื่อ เพื่อไม่ให้ข้อความปลอบใจโผล่หน้าแรก)
5. **การ์ดงาน:** แสดงแค่จำนวน หรือแสดงชื่องานค้าง 3 อันดับแรกด้วย? (แนะนำ: จำนวนอย่างเดียวใน v1)
6. **ผู้ใช้ปรับแต่ง:** ให้ผู้ใช้ซ่อน/จัดลำดับการ์ดเองไหม? (แนะนำ: ไม่ใน v1 ลำดับเป็นไปตาม Registry)

## Out of Scope (v1)
- การแก้ไข/เพิ่ม/ลบข้อมูลจากการ์ด และปุ่มลัดทำรายการ (เช่น จดรายจ่ายจากการ์ด)
- การเชื่อมข้อมูลข้ามฟีเจอร์ที่แก้ข้อมูล (เช่น "ทำแล้ว" → สร้างรายจ่ายอัตโนมัติ) และการวิเคราะห์ข้ามข้อมูล (อารมณ์กับการเงิน/อาหาร) — ต้องมี spec แยกและขอยืนยัน
- กราฟ แนวโน้มย้อนหลัง และการเปรียบเทียบกับช่วงก่อนหน้า
- การแจ้งเตือนนอกแอป
- ปุ่มซ่อนตัวเลข การจัดลำดับ/ซ่อนการ์ดรายใบโดยผู้ใช้ และการจำสถานะย่อ/ขยายข้ามการเปิดแอป (ดูข้อ 3 และ 6) — ย่อ/ขยายทั้งส่วนทำได้แล้ว
- การ์ดของ สับสนช่วยหน่อย / อันไหนถูกกว่า บอกมา / ไซส์ไหนคือฉัน
