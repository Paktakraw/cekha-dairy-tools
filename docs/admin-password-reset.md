# คู่มือผู้ดูแล: ช่วยผู้ใช้ที่ลืมรหัสผ่าน

ระบบยังไม่มีปุ่ม "ลืมรหัสผ่าน" (ตัดออกจากรอบแรก ตัดสินใจเมื่อ 2026-11-21) ผู้ใช้ที่ลืมรหัสผ่านต้องให้ **ผู้ดูแลตั้งรหัสใหม่ให้** ตามขั้นตอนด้านล่าง

## หลักการที่ต้องรู้
- **ดูรหัสผ่านเดิมไม่ได้** Supabase เก็บเป็นแฮช bcrypt (`auth.users.encrypted_password`) ย้อนกลับไม่ได้ ผู้ดูแลทำได้เพียง **ตั้งรหัสใหม่**
- ข้อมูลของผู้ใช้ (to-do, การเงิน ฯลฯ) ไม่หายเมื่อเปลี่ยนรหัส เพราะผูกกับ `user_id` ไม่ใช่รหัสผ่าน
- ผู้ใช้เข้าสู่ระบบด้วย **username** แต่ใน Supabase Auth ตัวตนคืออีเมลสังเคราะห์ `<username>@<โดเมน>` (โดเมนคือค่า `VITE_AUTH_EMAIL_DOMAIN` ใน `.env` ของแอป) ดังนั้นการค้นหาใน Authentication → Users ให้ค้นด้วย username
- ใช้เฉพาะผู้ดูแลที่เข้า Supabase Dashboard ได้ (สิทธิ์เจ้าของโปรเจกต์) อย่าส่ง service_role key ให้ใคร และอย่าใส่ในโค้ดของแอป

## ขั้นตอน

### 1. ยืนยันตัวตนผู้ขอก่อนเสมอ
ใครก็อ้างได้ว่าเป็นเจ้าของบัญชี ให้ขอข้อมูลที่ตรงกับตอนสมัคร อย่างน้อย **อีเมลและเบอร์โทร** แล้วเทียบกับตาราง `profiles` (ขั้นตอนที่ 2) ถ้าไม่ตรง **ห้ามเปลี่ยนรหัส** ห้ามบอกผู้ขอว่าข้อมูลไหนในระบบเป็นอย่างไร ให้เขาบอกมาเอง

### 2. หา username ของผู้ใช้
ถ้าผู้ใช้จำ username ไม่ได้ ให้ค้นใน **SQL Editor** จากข้อมูลที่เขาให้:
```sql
select username, first_name, last_name, email, phone
from public.profiles
where lower(email) = lower('someone@example.com')
   or phone = '0812345678';
```
(ตาราง `profiles` อ่านผ่าน SQL Editor ได้เพราะรันด้วยสิทธิ์ผู้ดูแล; แอปเองอ่านได้เฉพาะแถวของตัวเอง)

### 3. ตั้งรหัสใหม่ผ่าน SQL Editor
Dashboard ของ Supabase ไม่มีปุ่มตั้งรหัสผ่านใหม่ตรง ๆ ให้ (ทดลองแล้วไม่พบเมนู `…` สำหรับตั้งรหัส) และ "Send password recovery" ใช้ไม่ได้ เพราะอีเมลสังเคราะห์ไม่มีกล่องจดหมายจริง จึงใช้ SQL:

1. เปิด Supabase → **SQL Editor**
2. **เลือก role เป็น `postgres`** อยู่ในปุ่ม Dropdown Database > Run as เลือก postgres (ถ้าเป็น `authenticated` หรือ `anon` จะขึ้น `42501: permission denied for table users`)
3. รัน:
```sql
update auth.users
set encrypted_password = crypt('รหัสใหม่ชั่วคราว', gen_salt('bf')),
    updated_at = now()
where email = 'username@<โดเมน>';
```
- แทน `username`, `<โดเมน>` (ค่า `VITE_AUTH_EMAIL_DOMAIN`) และรหัสใหม่ให้ถูกต้อง (username ต้องเป็นตัวพิมพ์เล็ก)
- ตรวจผลลัพธ์: ต้องขึ้น `UPDATE 1` ถ้าขึ้น `UPDATE 0` แปลว่าไม่พบ username นั้น
- รหัสใหม่ต้องยาว 8 ตัวอักษรขึ้นไป และไม่เกิน 72 ไบต์ (ภาษาไทยตัวละ 3 ไบต์)
- ข้อความ SQL นี้จะถูกเก็บในประวัติของ SQL Editor ให้ลบรหัสออกจากประวัติ/ไม่เก็บ snippet

> **ห้ามทำตามคำแนะนำ `GRANT ... ON auth.users TO authenticated`** ที่ขึ้นเมื่อ error `42501` เพราะจะเปิดให้ผู้ใช้แอปทุกคนอ่าน/แก้ตารางผู้ใช้ (รวมแฮชรหัสผ่านของทุกบัญชี) ทางแก้คือเปลี่ยน role เป็น `postgres` เท่านั้น ถ้าเผลอ GRANT ไปแล้วให้รัน `revoke all on table auth.users from authenticated;` ด้วย role `postgres` ทันที

### 4. แจ้งผู้ใช้
- แจ้งรหัสชั่วคราวผ่านช่องทางที่เป็นส่วนตัว (ไม่โพสต์ในกลุ่ม)
- ให้ผู้ใช้เข้าสู่ระบบแล้วจดรหัสไว้ — ตอนนี้ยังไม่มีหน้าเปลี่ยนรหัสผ่านในแอป จึงยังเปลี่ยนเป็นรหัสที่ผู้ใช้ตั้งเองไม่ได้ (ดูข้อจำกัด)

### 5. ถ้าเข้าสู่ระบบไม่ได้หลังเปลี่ยนรหัส
| อาการ | สาเหตุที่เป็นไปได้ | วิธีแก้ |
|---|---|---|
| ขึ้น "ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง" | พิมพ์ username/รหัสผิด หรือ `UPDATE 0` | ตรวจ username (ไม่สนตัวพิมพ์ใหญ่เล็ก) และรัน SQL ซ้ำพร้อมดูผล `UPDATE 1` |
| SQL ขึ้น `42501: permission denied for table users` | SQL Editor รันด้วย role `authenticated`/`anon` | เปลี่ยน role เป็น `postgres` (ห้าม GRANT ตาม HINT) |
| ขึ้น "ลองหลายครั้งเกินไป" | ถูกจำกัดอัตรา (rate limit) ของ Supabase | รอสักครู่แล้วลองใหม่ |
| ไม่พบผู้ใช้ใน Authentication → Users | ผู้ใช้ยังไม่เคยสมัคร หรือสะกด username ผิด | ค้นด้วย `profiles` (ขั้นตอน 2) หรือให้สมัครใหม่ |

## ข้อจำกัดและแนวทางต่อยอด
- วิธีนี้ **ต้องมีผู้ดูแลลงมือทุกครั้ง** เหมาะกับผู้ใช้ไม่กี่คน
- ผู้ใช้ **เปลี่ยนรหัสผ่านเองไม่ได้** (ยังไม่มีหน้าเปลี่ยนรหัสผ่าน อยู่นอก scope ของ Phase 14)
- ถ้าผู้ใช้เพิ่มขึ้น ให้พิจารณา **รีเซ็ตทางอีเมลจริง** (ส่งลิงก์ไปอีเมลใน `profiles` ผ่าน Edge Function + SMTP) หรือ **recovery code** — ต้องทำเป็น Phase ใหม่พร้อม spec ดู [future-login.md](future-login.md)
