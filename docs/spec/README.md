# เอกสาร Spec ระดับผลิตภัณฑ์และระบบ

โฟลเดอร์นี้เก็บเอกสารภาพรวมของทั้งแอป **เสขาประจำวัน (Daily Life Portal)** ต่างจาก `docs/features/` ที่เก็บ spec รายฟีเจอร์

| ไฟล์ | เนื้อหา | ผู้อ่านหลัก |
|---|---|---|
| [PRD.md](PRD.md) | Product Requirements แบบเรียบง่ายสำหรับฝั่งธุรกิจ: สรุป ปัญหา/เป้าหมาย ผู้ใช้ เครื่องมือที่มี กติกากลาง สิ่งที่ยังไม่ทำ ข้อจำกัด ประวัติการพัฒนา | เจ้าของผลิตภัณฑ์ ผู้บริหาร ฝั่งธุรกิจ |
| [system-design.md](system-design.md) | System Design: สถาปัตยกรรม โครงสร้างโค้ด Auth/Theme Database schema (ER, ตาราง, RLS, ฟังก์ชัน) Workflow แบบ sequence diagram และแนวทาง error/security/deploy | นักพัฒนา |

เอกสารที่เกี่ยวข้อง
- Spec รายฟีเจอร์: [`docs/features/`](../features/)
- เอกสารการทดสอบ (test case และผลทดสอบ): [`docs/testing/`](../testing/)
- กฎการทำงานและโครงสร้างโปรเจกต์: [`CLAUDE.md`](../../CLAUDE.md) ความคืบหน้า: [`PROGRESS.md`](../../PROGRESS.md)

## กฎการอัปเดต
ก่อนเปิด Pull Request ต้องอัปเดตเอกสารในโฟลเดอร์นี้ (และ `docs/testing/`) ให้ตรงกับโค้ดที่เปลี่ยน ดูกฎเต็มที่ [CLAUDE.md](../../CLAUDE.md) ข้อ 10.11 และเช็กลิสต์ท้ายไฟล์นี้

### เช็กลิสต์ก่อนเปิด PR (ส่วน spec)
- [ ] PRD: เพิ่ม/แก้ตารางเครื่องมือ (หัวข้อ 4), สิ่งที่ยังไม่ทำ/ข้อจำกัด (หัวข้อ 6–7), ประวัติการพัฒนา (หัวข้อ 8) และเลขเวอร์ชัน — ใช้ภาษาธุรกิจ ไม่ใส่รายละเอียดทางเทคนิค
- [ ] System design: อัปเดตโครงสร้างโฟลเดอร์/Registry ถ้ามีฟีเจอร์ใหม่, ER diagram และตาราง schema ถ้ามี migration ใหม่, sequence diagram ถ้า workflow เปลี่ยน
- [ ] เลขเวอร์ชันและวันที่ท้ายเอกสารตรงกับ `package.json`
