# แนวทางเพิ่ม Login จริงในอนาคต

ตอนนี้แอปใช้ **Supabase Anonymous Sign-in**: เปิดแอปครั้งแรกระบบสร้างผู้ใช้แบบไม่ระบุตัวตนให้อัตโนมัติ ข้อมูลทุกตารางผูกกับ `user_id` ของผู้ใช้นั้น

**ข้อจำกัดของแบบไม่ระบุตัวตน:** ตัวตนผูกกับเบราว์เซอร์ (session ใน localStorage) ถ้าล้างข้อมูลเบราว์เซอร์ เปลี่ยนเครื่อง หรือเปิดจากเบราว์เซอร์อื่น จะเป็นผู้ใช้ใหม่และมองไม่เห็นข้อมูลเดิม การเพิ่ม Login จริงแก้ปัญหานี้

## ข้อดีของการออกแบบปัจจุบัน

ไม่ต้องแก้โครงสร้างฐานข้อมูลหรือโค้ดของฟีเจอร์เลย เพราะ:
- ทุกตารางใช้ `user_id` อ้างอิง `auth.users` และ RLS (`auth.uid() = user_id`) อยู่แล้ว ไม่สนว่าผู้ใช้จะเป็น anonymous หรือบัญชีจริง
- จุดที่จัดการ session/user อยู่ที่เดียว คือ `src/app/providers/AuthProvider.tsx` (+ `useAuth`)
- มี `ProtectedRoute` และ route `/login` (โครงเปล่า) เตรียมไว้แล้ว

## ขั้นตอนที่แนะนำ

### 1. เปิดวิธีล็อกอินบน Supabase
**Authentication → Providers** เปิด Email และ/หรือ OAuth (เช่น Google) ตั้ง **Site URL** และ **Redirect URLs** ให้ตรงกับโดเมนจริงและ `http://localhost:5173` สำหรับพัฒนา

### 2. ผูกผู้ใช้ anonymous เดิมเข้ากับบัญชีจริง (หัวใจสำคัญ ข้อมูลไม่หาย)
เมื่อผู้ใช้ที่เป็น anonymous อยู่แล้ว "สมัคร/ผูกบัญชี" ให้ **อัปเกรดผู้ใช้เดิม** แทนการสร้างผู้ใช้ใหม่ `user_id` จึงคงเดิมและข้อมูลทั้งหมดยังอยู่:

```ts
// ผูกด้วยอีเมล + รหัสผ่าน (ผู้ใช้จะได้รับอีเมลยืนยัน)
await supabase.auth.updateUser({ email, password })

// หรือผูกด้วย OAuth
await supabase.auth.linkIdentity({ provider: 'google' })
```

### 3. ขยาย `AuthProvider`
เพิ่มฟังก์ชันใน context (และ type ใน `AuthContext.ts`) เช่น `linkAccount(email, password)`, `signIn(email, password)`, `signOut()` และบอกสถานะ `isAnonymous` (ดูจาก `user.is_anonymous`) เพื่อให้ UI รู้ว่าควรแสดงปุ่ม "บันทึกข้อมูลของฉันด้วยอีเมล" หรือแสดงอีเมลของบัญชี

### 4. ทำหน้า Login / สมัครสมาชิก
แทนที่ `src/pages/LoginPage.tsx` ด้วยฟอร์มจริง (ใช้ `Input`, `FormActions` จาก shared UI) ข้อความเป็นภาษาไทย และเพิ่มปุ่มออกจากระบบใน Sidebar

### 5. ตัดสินใจเรื่อง `ProtectedRoute`
มี 2 ทาง:
- **แบบผสม (แนะนำ):** คงการเข้าใช้แบบ anonymous อัตโนมัติ และให้ผู้ใช้กดผูกบัญชีเมื่อพร้อม ผู้ใช้ใหม่ไม่ต้องเจอกำแพง Login
- **แบบบังคับ Login:** เอา `signInAnonymously()` ออกจาก `AuthProvider` แล้วให้ `ProtectedRoute` redirect ไป `/login` เมื่อยังไม่มี user (โค้ดรองรับไว้แล้ว)

## กรณีที่ต้องระวัง

- **ผู้ใช้ล็อกอินเข้าบัญชีเก่าจากเครื่องใหม่ที่เคยใช้แบบ anonymous มาก่อน:** การ `signIn` จะสลับไปเป็นผู้ใช้ของบัญชีนั้น ข้อมูลของ anonymous บนเครื่องนี้จะไม่ถูกรวมให้เอง ถ้าต้องการรวม ต้องเขียน Database Function (security definer) ที่ย้ายแถวจาก `user_id` เดิมไป `user_id` ใหม่ แล้วเรียกก่อน sign in หรือแจ้งผู้ใช้ให้ชัดว่าข้อมูลจะไม่ถูกรวม
- **ผู้ใช้ anonymous ที่ไม่เคยผูกบัญชีจะสะสมในระบบ:** ตั้งงานล้างข้อมูลเป็นระยะ (Supabase มีตัวช่วยจัดการผู้ใช้) และพิจารณาเปิด CAPTCHA ที่ Authentication → Attack Protection เพื่อกันการสร้างผู้ใช้ anonymous จำนวนมาก
- **อีเมลยืนยัน:** ถ้าเปิดการยืนยันอีเมล การ `updateUser({ email })` จะยังไม่เปลี่ยนจนกว่าผู้ใช้จะกดลิงก์ในอีเมล ต้องแสดงข้อความแจ้งผู้ใช้
- **RLS ไม่ต้องแก้:** นโยบายเดิมครอบคลุมทั้ง anonymous และบัญชีจริง อย่าเพิ่มนโยบายแบบ public เพื่อ "ทำให้ง่ายขึ้น"
- **Environment:** ยังใช้เฉพาะ publishable key ห้ามนำ secret / service_role key ไปไว้ฝั่ง client แม้ตอนทำ Login

## เช็กลิสต์

- [ ] เปิด Provider และตั้ง Redirect URLs แล้ว
- [ ] `AuthProvider` มี `linkAccount`, `signIn`, `signOut`, `isAnonymous`
- [ ] หน้า Login/สมัครสมาชิกเป็นภาษาไทย มี Loading / Error / Toast
- [ ] ทดสอบ: anonymous → ผูกบัญชี → ข้อมูลเดิมยังอยู่ (`user_id` ไม่เปลี่ยน)
- [ ] ทดสอบ: ออกจากระบบ → ล็อกอินใหม่จากเครื่องอื่น → เห็นข้อมูลเดิม
- [ ] ทดสอบ: ผู้ใช้สองคนมองไม่เห็นข้อมูลของกันและกัน (RLS)
